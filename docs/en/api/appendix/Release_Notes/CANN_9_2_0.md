# C API

<!-- md-trans-meta sourceCommit=32fdd99fd558eb76c67d4ee380c10f94af85c2ab translatedAt=2026-10-29T11:15:46.691Z pushedAt=2026-10-29T11:27:54.702Z nl=2 -->

CANN 9.2.0 continues to enhance the C API on top of CANN 9.1.0. This version introduces capabilities such as cube computation and data movement configuration, Reg computation and movement, cache and special register control, supplements function-return-value overloads for a large number of Reg APIs, and unifies public header files, API naming, and parameter types. Meanwhile, some legacy names, implicit-position overloads, and composite synchronization APIs enter the deprecation phase.

## New Features

### System, Cache, and Control

- [asc_disable_dma_atomic](../../SIMD-API/c_api/atomic/datamove_atomic/asc_disable_dma_atomic.md): Disables the atomic operation after the data movement atomic operation completes, preventing an already enabled atomic operation from affecting subsequent movements. This API supports Atlas A2 products and Atlas A3 products, as well as Ascend 950PR&950DT products.
- [asc_set_atomic_add_int32](../../SIMD-API/c_api/atomic/datamove_atomic/asc_set_atomic_add.md), [asc_set_atomic_max_int32](../../SIMD-API/c_api/atomic/datamove_atomic/asc_set_atomic_max.md), and [asc_set_atomic_min_int32](../../SIMD-API/c_api/atomic/datamove_atomic/asc_set_atomic_min.md): Enable the `int32_t` atomic add, atomic maximum, and atomic minimum operations during data movement, respectively, using explicit data type suffixes to replace the old `*_int` naming. This group of APIs supports Atlas A2 products and Atlas A3 products, as well as Ascend 950PR&950DT products.
- [asc_get_pipe_mte2_idle_slot_count](../../SIMD-API/c_api/experimental/asc_get_pipe_idle_slot_count.md), [asc_get_pipe_mte3_idle_slot_count](../../SIMD-API/c_api/experimental/asc_get_pipe_idle_slot_count.md), [asc_get_pipe_v_idle_slot_count](../../SIMD-API/c_api/experimental/asc_get_pipe_idle_slot_count.md), [asc_get_pipe_m_idle_slot_count](../../SIMD-API/c_api/experimental/asc_get_pipe_idle_slot_count.md), [asc_get_pipe_mte1_idle_slot_count](../../SIMD-API/c_api/experimental/asc_get_pipe_idle_slot_count.md), and [asc_get_pipe_fix_idle_slot_count](../../SIMD-API/c_api/experimental/asc_get_pipe_idle_slot_count.md): Query the current number of idle slots in the PIPE_MTE2, PIPE_MTE3, PIPE_V, PIPE_M, PIPE_MTE1, and PIPE_FIX issue queues, respectively, to observe how many pending instructions each queue can still accept. This group of APIs supports only Ascend 950PR&950DT products and is an experimental feature. To use it, include `c_api/experimental/asc_get_pipe_idle_slot_count.h` and define `CANN_ASC_USE_EXPERIMENTAL`.
- [asc_set_scalar_cache_mode](../../SIMD-API/c_api/cache_ctrl/asc_set_scalar_cache_mode.md), [asc_get_scalar_load_cache_mode](../../SIMD-API/c_api/cache_ctrl/asc_get_scalar_load_cache_mode.md), and [asc_get_scalar_store_cache_mode](../../SIMD-API/c_api/cache_ctrl/asc_get_scalar_store_cache_mode.md): Support setting the L2 Cache management policies for scalar reads and writes to Global Memory separately, as well as reading back the current scalar read and write policies. The configured policies remain in effect until they are modified by calling the setting API again. This group of APIs supports only Ascend 950PR&950DT products.
- [asc_set_saturation_flag](../../SIMD-API/c_api/spr/asc_set_saturation_flag.md) and [asc_get_saturation_flag](../../SIMD-API/c_api/spr/asc_get_saturation_flag.md): Support setting or querying the saturation switch for floating-point, FP8, integer, and type conversion scenarios through [asc_saturation_mode](../../SIMD-API/c_api/defs/enum/asc_saturation_mode.md). [asc_set_saturation_strategy](../../SIMD-API/c_api/spr/asc_set_saturation_strategy.md) and [asc_get_saturation_strategy](../../SIMD-API/c_api/spr/asc_get_saturation_strategy.md) support switching between and querying the per-instruction/API path configuration and the global saturation configuration through [asc_override_strategy](../../SIMD-API/c_api/defs/enum/asc_override_strategy.md). Among these, the global saturation switch for the type conversion scenario takes effect only when the global saturation configuration is used. This group of APIs supports only Ascend 950PR&950DT products.
- The existing [asc_get_system_cycle](../../SIMD-API/c_api/utils/sys_var/asc_get_system_cycle.md) from CANN 9.1.0 is still used to read the raw cycle count value. This API supports Atlas A2 products and Atlas A3 products, as well as Ascend 950PR&950DT products.
- [asc_nop](../../SIMD-API/c_api/utils/sys_misc/asc_nop.md): Generates a no-operation instruction that performs no actual computation. Each call blocks one pipeline stage. This API supports only Ascend 950PR&950DT products.

### Cube Computation and Data Movement

- [asc_disable_hf32](../../SIMD-API/c_api/cube_compute/asc_disable_hf32.md): Disables the HF32 mode of Mmad computation so that the `float` data in the L0A Buffer and L0B Buffer is not rounded before participating in computation; [asc_disable_hif8](../../SIMD-API/c_api/cube_compute/asc_disable_hif8.md): Disables the HiF8 mode so that when both the left and right matrices are `fp8_e4m3fn_t`, they are no longer converted to `hifloat8_t` but directly participate in matrix multiplication. Both APIs are cube computation configuration APIs that take effect only on the AIC. Among them, `asc_disable_hf32` supports Atlas A2 products, Atlas A3 products, and Ascend 950PR&950DT products, while `asc_disable_hif8` supports only Ascend 950PR&950DT products.
- [asc_set_hf32_round_mode](../../SIMD-API/c_api/cube_compute/asc_set_hf32_round_mode.md): Uses the [asc_hf32_round_mode](../../SIMD-API/c_api/defs/enum/asc_hf32_round_mode.md) enum to configure the HF32 rounding mode. The HF32 mode must be enabled before calling this API. This API supports Atlas A2 products, Atlas A3 products, and Ascend 950PR&950DT products.
- [asc_set_gm2l1_padding](../../SIMD-API/c_api/cube_datamove/asc_set_gm2l1_padding.md): Configures the padding value for high-dimensional split data movement from GM to the L1 Buffer; [asc_set_l12l0a_3d_padding](../../SIMD-API/c_api/cube_datamove/asc_set_l12l0a_3d_padding.md) and [asc_set_l12l0b_3d_padding](../../SIMD-API/c_api/cube_datamove/asc_set_l12l0b_3d_padding.md): Configure the padding values for 3D im2col data movement of the left and right matrices, respectively; [asc_set_l13d_rpt_b](../../SIMD-API/c_api/cube_datamove/asc_set_l13d_rpt_b.md): Configures the parameters required for the right matrix to use repeat data movement in 3D im2col mode. This group of APIs takes effect only on the AIC. Among them, `asc_set_gm2l1_padding` and `asc_set_l12l0a_3d_padding` support Atlas A2 products, Atlas A3 products, and Ascend 950PR&950DT products, while the remaining APIs support only Ascend 950PR&950DT products.
- [asc_set_l0c_copy_config](../../SIMD-API/c_api/cube_datamove/asc_set_l0c_copy_config.md): Configures the starting index of the in-band tensor quantization and tensor activation parameters in the Fixpipe Buffer when the L0C Buffer is moved out, and supports initializing the global UnitFlag state; [asc_set_l0c_copy_channel_para](../../SIMD-API/c_api/cube_datamove/asc_set_l0c_copy_channel_para.md): Configures the address offset between adjacent rows of the source Nz matrix during Nz2DN format conversion; [asc_set_l0c_copy_nz_para](../../SIMD-API/c_api/cube_datamove/asc_set_l0c_copy_nz_para.md): Configures the parameters required for in-band Nz-to-ND/DN conversion; [asc_set_l0c_copy_relu_alpha](../../SIMD-API/c_api/cube_datamove/asc_set_l0c_copy_relu_alpha.md) and [asc_set_l0c_copy_lrelu_alpha](../../SIMD-API/c_api/cube_datamove/asc_set_l0c_copy_lrelu_alpha.md): Configure the scaling factor for in-band scalar activation. This group of configurations is used by the subsequent L0C Buffer move-out APIs and takes effect only on the AIC. Among them, `asc_set_l0c_copy_config` and `asc_set_l0c_copy_lrelu_alpha` support Atlas A2 products, Atlas A3 products, and Ascend 950PR&950DT products, while the remaining APIs support only Ascend 950PR&950DT products. The new API `asc_set_l0c_copy_lrelu_alpha` provides only the `float` parameter form; the existing [asc_set_l0c2gm_lrelu_alpha](../../SIMD-API/c_api/deprecated_interface/asc_set_l0c2gm_lrelu_alpha_deprecated.md) from CANN 9.1.0 still provides the `half&` and `float&` parameter forms.

### Scalar Computation

- [asc_load_dev](../../SIMD-API/c_api/scalar_compute/scalar_load/asc_load_dev.md): Reads integer scalar data directly from Global Memory without going through the Data Cache. It is suitable for scenarios where multiple cores access GM addresses that cannot be aligned to Cache Line boundaries and where Cache Line-granularity data overwrite must be avoided. This API is supported only on Ascend 950PR&950DT products.
- [asc_float2half_ro](../../SIMD-API/c_api/scalar_compute/scalar_convert/asc_float2half.md): Converts `float` to `half` on the scalar pipeline and returns the result directly, with the rounding mode fixed to ODD (round-to-nearest-odd). This API is supported only on Ascend 950PR&950DT products.

### Memory Vector Computation

- [asc_transto5hd](../../SIMD-API/c_api/vector_compute/vector_permute_sel/asc_transto5hd.md): [asc_transto5hd_b8](../../SIMD-API/c_api/vector_compute/vector_permute_sel/asc_transto5hd.md), [asc_transto5hd_b16](../../SIMD-API/c_api/vector_compute/vector_permute_sel/asc_transto5hd.md), and [asc_transto5hd_b32](../../SIMD-API/c_api/vector_compute/vector_permute_sel/asc_transto5hd.md) are officially added to the public header file for NCHW-to-NC1HWC0 format conversion or two-dimensional matrix data block transpose. A single Repeat processes 512 bytes (16 DataBlocks), and multiple Repeat operations are supported. This group of APIs supports Atlas A2 products, Atlas A3 products, and Ascend 950PR&950DT products.
- [asc_set_vector_mask](../../SIMD-API/c_api/vector_compute/vector_mask_config/asc_set_vector_mask.md) adds support for Ascend 950PR&950DT products, allowing the mask register to be configured outside the Vector Function and used together with Reg vector computation APIs.

### Reg Computation and Reg Data Movement

All APIs added in this section are supported only on Ascend 950PR&950DT products and are called in the Vector Function of the AIV.

- [asc_duplicate_highest](../../SIMD-API/c_api/reg_compute/reg_broadcast/asc_duplicate_highest.md) and [asc_duplicate_highest_merge](../../SIMD-API/c_api/reg_compute/reg_broadcast/asc_duplicate_highest_merge.md): Broadcast the element with the largest subscript in the source operand to the destination positions selected by the mask, setting the unselected positions to 0 or retaining their original values, respectively. [asc_duplicate_merge](../../SIMD-API/c_api/reg_compute/reg_broadcast/asc_duplicate_merge.md) and [asc_duplicate_scalar_merge](../../SIMD-API/c_api/reg_compute/reg_broadcast/asc_duplicate_scalar_merge.md): Broadcast the element with the smallest subscript in the source operand or a given scalar to the destination positions selected by the mask, respectively, and retain the original values of the unselected positions.
- [asc_mask](../../SIMD-API/c_api/reg_compute/reg_copy/asc_mask.md): Supports masked copy of a vector data register or mask register through the function return value. [asc_extract_mask](../../SIMD-API/c_api/reg_compute/reg_copy/asc_extract_mask.md): Extracts and expands bits from a specified data block of a `uint16_t` or `uint32_t` vector data register to generate a mask register return value.
- [asc_pack_to_low](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_pack_to_low.md) and [asc_pack_to_high](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_pack_to_high.md): Select the even bits (`vector_bool`), the lower 8 bits (b16), or the lower 16 bits (b32) of the source operand, and write them to the lower half or upper half of the destination operand, respectively.
- [asc_unsqueeze](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_unsqueeze.md) adds [asc_unsqueeze_s8](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_unsqueeze.md), [asc_unsqueeze_u8](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_unsqueeze.md), [asc_unsqueeze_s16](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_unsqueeze.md), [asc_unsqueeze_u16](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_unsqueeze.md), [asc_unsqueeze_s32](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_unsqueeze.md), and [asc_unsqueeze_u32](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_unsqueeze.md), supporting obtaining the mask prefix count result through the function return value: the first element is 0, the `i`-th element is the number of 1s in the 0th through `i-1`-th elements of the mask, and the highest bit of the mask is not counted.
- [asc_fma](../../SIMD-API/c_api/reg_compute/reg_fused/asc_fma.md), [asc_mula](../../SIMD-API/c_api/reg_compute/reg_fused/asc_mula.md), and [asc_mul_scalar_float2half_rn](../../SIMD-API/c_api/reg_compute/reg_fused/asc_mul_scalar_float2half_rn.md): Support three-source fused multiply-add, the destination operand participating in multiply-add as an accumulator, and multiplying a `float` vector by a scalar and then converting the result to `half` in RINT mode and writing it to specified odd or even positions, respectively. Among them, `asc_fma` had only a Memory vector computation API in CANN 9.1.0, and the Reg API is newly added in this version.
- [asc_exp_sub](../../SIMD-API/c_api/reg_compute/reg_fused/asc_exp_sub.md) adds the [asc_exp_sub_half2float](../../SIMD-API/c_api/reg_compute/reg_fused/asc_exp_sub.md) API, which supports explicitly selecting odd-indexed or even-indexed elements of a `half` source operand, converting them to `float`, and then computing the natural exponential function with the difference of the two sources as the exponent element by element. [asc_log](../../SIMD-API/c_api/reg_compute/reg_arith/asc_log.md) adds a Reg element-wise natural logarithm computation API.
- [asc_squeeze_and_storeunalign_init](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_squeeze_and_storeunalign_init.md) clears the AR special register. [asc_squeeze_and_storeunalign](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_squeeze_and_storeunalign.md) filters vector register elements by mask, moves the results out consecutively to a UB address that is not 32-byte aligned, and accumulates the total number of valid data bytes in the AR register. [asc_squeeze_and_storeunalign_finalize](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_squeeze_and_storeunalign_finalize.md) writes the tail block that is less than 32 Byte and temporarily stored in the unaligned register to UB.
- [asc_get_squeeze_status](../../SIMD-API/c_api/spr/asc_get_squeeze_status.md): Reads the valid data length saved in the AR special register by the squeeze operation. [asc_storealign_squeeze_status](../../SIMD-API/c_api/reg_compute/store/asc_storealign_squeeze_status.md) and [asc_storealign_squeeze_status_postupdate](../../SIMD-API/c_api/reg_compute/store/asc_storealign_squeeze_status_postupdate.md): Move this length out to UB, and the latter also automatically updates the destination address by byte offset after writing.
- Reg-aligned move-in adds mode APIs with explicit semantics: [asc_loadalign_brc_datablock](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_brc_datablock.md) broadcasts a 32 Byte DataBlock, [asc_loadalign_brc_elem](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_brc_elem.md) broadcasts one element, [asc_loadalign_brc_elem2datablock](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_brc_elem2datablock.md) reads eight elements consecutively and broadcasts each element as a DataBlock, and [asc_loadalign_unpack4](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_unpack4.md) reads VL/4-length data and pads three zeros after each element; the corresponding [asc_loadalign_brc_datablock_postupdate](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_brc_datablock_postupdate.md), [asc_loadalign_brc_elem_postupdate](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_brc_elem_postupdate.md), [asc_loadalign_brc_elem2datablock_postupdate](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_brc_elem2datablock_postupdate.md), and [asc_loadalign_unpack4_postupdate](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_unpack4_postupdate.md) automatically update the source address after the move-in. The new return-value APIs [asc_loadalign_datablock_strided](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_datablock_strided.md), [asc_loadalign_mask](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_mask.md), [asc_loadalign_mask_downsample](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_mask_downsample.md), and [asc_loadalign_mask_upsample](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_mask_upsample.md) support strided move-in of eight DataBlocks, and directly return the original, even-bit downsampled, and bit-doubled upsampled mask registers, respectively.
- [asc_storealign_pack_quarter](../../SIMD-API/c_api/reg_compute/store/asc_storealign_pack_quarter.md) and [asc_storealign_pack_quarter_postupdate](../../SIMD-API/c_api/reg_compute/store/asc_storealign_pack_quarter_postupdate.md): compress and move out the lower 8 bits of valid 32-bit Reg elements to UB according to the mask; the latter automatically updates the destination address by the offset after the move-out.
- The [asc_update_addr_reg](../../SIMD-API/c_api/reg_compute/reg_addr_reg/asc_update_addr_reg.md) API family adds [asc_update_addr_reg_b8](../../SIMD-API/c_api/reg_compute/reg_addr_reg/asc_update_addr_reg.md), [asc_update_addr_reg_b16](../../SIMD-API/c_api/reg_compute/reg_addr_reg/asc_update_addr_reg.md), and [asc_update_addr_reg_b32](../../SIMD-API/c_api/reg_compute/reg_addr_reg/asc_update_addr_reg.md), which compute the address offset of 1- to 4-dimensional loops in units of 1 Byte, 2 Byte, and 4 Byte, respectively. They use [addr_reg](../../SIMD-API/c_api/defs/type/data_type_definition.md#address-register) to store the offset and work with the Reg move-in and move-out APIs to complete iterative addressing, replacing the original [iter_reg](../../SIMD-API/c_api/deprecated_interface/asc_create_iter_reg_deprecated.md) API family.

## Enhancements

### Reg Computation

- Added overloads in the form of function return values for Reg arithmetic, comparison, logic, fused, reduction, broadcast, index generation, type conversion, data load-in, and permutation APIs. This involves [asc_add](../../SIMD-API/c_api/reg_compute/reg_arith/asc_add.md), [asc_sub](../../SIMD-API/c_api/reg_compute/reg_arith/asc_sub.md), [asc_mul](../../SIMD-API/c_api/reg_compute/reg_arith/asc_mul.md), [asc_div](../../SIMD-API/c_api/reg_compute/reg_arith/asc_div.md), [asc_max](../../SIMD-API/c_api/reg_compute/reg_arith/asc_max.md), [asc_min](../../SIMD-API/c_api/reg_compute/reg_arith/asc_min.md), [asc_abs](../../SIMD-API/c_api/reg_compute/reg_arith/asc_abs.md), [asc_neg](../../SIMD-API/c_api/reg_compute/reg_arith/asc_neg.md), [asc_sqrt](../../SIMD-API/c_api/reg_compute/reg_arith/asc_sqrt.md), [asc_exp](../../SIMD-API/c_api/reg_compute/reg_arith/asc_exp.md), comparison and scalar comparison APIs, [asc_and](../../SIMD-API/c_api/reg_compute/reg_logic/asc_and.md), [asc_or](../../SIMD-API/c_api/reg_compute/reg_logic/asc_or.md), [asc_not](../../SIMD-API/c_api/reg_compute/reg_logic/asc_not.md), [asc_xor](../../SIMD-API/c_api/reg_compute/reg_logic/asc_xor.md), shift APIs, [asc_abs_sub](../../SIMD-API/c_api/reg_compute/reg_fused/asc_abs_sub.md), [asc_relu](../../SIMD-API/c_api/reg_compute/reg_fused/asc_relu.md), reduction APIs, [asc_duplicate](../../SIMD-API/c_api/reg_compute/reg_broadcast/asc_duplicate.md), [asc_duplicate_scalar](../../SIMD-API/c_api/reg_compute/reg_broadcast/asc_duplicate_scalar.md), [asc_arange](../../SIMD-API/c_api/reg_compute/reg_index/asc_arange.md), [asc_arange_descend](../../SIMD-API/c_api/reg_compute/reg_index/asc_arange.md), [asc_load](../../SIMD-API/c_api/reg_compute/load/asc_load.md), [asc_loadalign](../../SIMD-API/c_api/reg_compute/load/asc_loadalign.md), [asc_gather_datablock](../../SIMD-API/c_api/reg_compute/ub_gather/asc_gather_datablock.md), [asc_half2int16](../../SIMD-API/c_api/reg_compute/reg_convert/asc_half2int16.md), and other Reg type conversion APIs.
- `asc_div` adds `int16_t`, `uint16_t`, `int32_t`, and `uint32_t` overloads; the register-source [asc_gather](../../SIMD-API/c_api/reg_compute/reg_gather/asc_gather.md) adds a `vector_float` overload, and the UB-source [asc_gather](../../SIMD-API/c_api/reg_compute/ub_gather/asc_gather.md) adds `int8_t` and `uint8_t` same-width output overloads. The documentation and header file ownership of the two types of APIs are split accordingly: the UB-source gather API uses `c_api/reg_compute/gather/ub_gather.h`, and the register-source gather API uses `c_api/reg_compute/compute/reg_gather.h`.
- The iteration offset parameter of the Reg move-in and move-out APIs is migrated from `iter_reg` to `addr_reg`, working together with the newly added `asc_update_addr_reg_b8`, `asc_update_addr_reg_b16`, and `asc_update_addr_reg_b32` in this version to implement circular addressing.
- [asc_min_scalar](../../SIMD-API/c_api/reg_compute/reg_arith/asc_min_scalar.md) and [asc_ne](../../SIMD-API/c_api/reg_compute/reg_compare/asc_ne.md) add `bfloat16_t` overloads.
- `asc_duplicate` and `asc_duplicate_scalar` add `fp8_e8m0_t` reference-output overloads, and supplement the function return value forms including `fp8_e8m0_t`; [asc_madd](../../SIMD-API/c_api/reg_compute/reg_fused/asc_madd.md) adds a `bfloat16_t` overload.
- [asc_store](../../SIMD-API/c_api/reg_compute/store/asc_store.md) supplements a public overload with the `half` data type and a `count` parameter, supporting specification of the number of valid elements moved out from Reg to UB.
- Type conversion APIs supplement explicit source/destination position parameters and function return value forms, uniformly expressing positions through [asc_position_mode](../../SIMD-API/c_api/defs/enum/asc_position_mode.md) or [asc_position_quarter_mode](../../SIMD-API/c_api/defs/enum/asc_position_quarter_mode.md); even and odd positions can also directly use the [ASC_POSITION_EVEN](../../SIMD-API/c_api/defs/enum/asc_position_mode.md) and [ASC_POSITION_ODD](../../SIMD-API/c_api/defs/enum/asc_position_mode.md) constants, no longer relying on the `_v2`, `_v3`, and `_v4` suffixes to infer positions.
- Added overloads in the form of function return values for the [asc_pack_to_high](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_pack_to_high.md) and [asc_pack_to_low](../../SIMD-API/c_api/reg_compute/reg_permute_sel/asc_pack_to_low.md) APIs.
- [asc_update_addr_reg](../../SIMD-API/c_api/reg_compute/reg_addr_reg/asc_update_addr_reg.md) supplements function and constraint descriptions, and provides a directly runnable call example.

### Cube Computation and Data Movement

- [asc_mmad](../../SIMD-API/c_api/cube_compute/asc_mmad.md) and [asc_mmad_mx](../../SIMD-API/c_api/cube_compute/asc_mmad_mx.md) add overloads that explicitly pass the Bias start address, supporting initialization of the result matrix with the Bias matrix in the BiasTable Buffer. The newly added overloads are supported only on Ascend 950PR&950DT products.
- [asc_copy_gm2l1](../../SIMD-API/c_api/cube_datamove/asc_copy_gm2l1/asc_copy_gm2l1.md), [asc_copy_gm2l1_align](../../SIMD-API/c_api/cube_datamove/asc_copy_gm2l1_align.md), [asc_copy_gm2l1_nd2nz](../../SIMD-API/c_api/cube_datamove/asc_copy_gm2l1_nd2nz/asc_copy_gm2l1_nd2nz.md), [asc_copy_gm2l1_dn2nz](../../SIMD-API/c_api/cube_datamove/asc_copy_gm2l1_dn2nz.md), and the L0C Buffer move-out APIs add parameterized overloads that support using enums to configure data movement behaviors such as L2 Cache, quantization, activation, format conversion, and UnitFlag. The newly added strongly-typed overloads are supported only on Ascend 950PR&950DT products.
- [asc_copy_l0c2l1](../../SIMD-API/c_api/cube_datamove/asc_copy_l0c2l1/asc_copy_l0c2l1.md) adds matrix move-out overloads and in-band configuration capabilities for Ascend 950PR&950DT products. ## Bug Fixes

- Fixed the insufficient bit width of the `n_burst` parameter in aligned data movement APIs such as [asc_copy_gm2ub_align](../../SIMD-API/c_api/vector_datamove/asc_copy_gm2ub_align/asc_copy_gm2ub_align.md) and [asc_copy_ub2gm_align](../../SIMD-API/c_api/vector_datamove/asc_copy_ub2gm_align/asc_copy_ub2gm_align.md) under the 3510 architecture, and extended `n_burst` in the related overloads to `uint32_t`.
- Fixed the issue where [asc_store](../../SIMD-API/c_api/reg_compute/store/asc_store.md) did not perform address Post Update post-processing during unaligned move-out under the 3510 architecture, resulting in incorrect data movement results.
- Fixed the pass-by-value issue of the address or address register in Post Update data movement APIs: the UB source address and `addr_reg` offset of [asc_loadunalign_postupdate](../../SIMD-API/c_api/reg_compute/load/asc_loadunalign_postupdate.md), as well as the UB destination addresses of [asc_storealign_postupdate](../../SIMD-API/c_api/reg_compute/store/asc_storealign_postupdate.md), [asc_storealign_1st_postupdate](../../SIMD-API/c_api/reg_compute/store/asc_storealign_1st_postupdate.md), and [asc_storealign_pack_postupdate](../../SIMD-API/c_api/reg_compute/store/asc_storealign_pack_postupdate.md), are changed to pass-by-reference to ensure that the updated results after API execution can be written back to the caller.
- Fixed the issue where the `vector_bool` overload of [asc_loadalign_postupdate](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_postupdate.md) was missing the `offset` parameter, so that the public declaration is consistent with the implementation.
- Fixed the issue where [asc_loadalign_downsample_postupdate](../../SIMD-API/c_api/reg_compute/load/asc_loadalign_downsample_postupdate.md) for `vector_int4x2_t` and the `asc_loadalign_postupdate` overloads with the `block_stride` and `repeat_stride` parameters only updated a local copy of the source pointer, ensuring that the source address update can be written back to the caller and that subsequent move-in continues from the correct position across consecutive calls.
- Fixed the pass-by-value issue of the destination vector data register `dst` in `asc_squeeze_and_storeunalign`, changing it to pass-by-reference to ensure that the squeeze result can be written back to the caller.
- Fixed the issue where the [asc_sync_subblock_wait](../../SIMD-API/c_api/sync/inter_core_sync/asc_sync_subblock_wait.md) macro passed an extra `pipe` parameter to the underlying API under the 2201 architecture.
- Fixed the issue where some [asc_sub_relu_sync](../../SIMD-API/c_api/deprecated_interface/asc_sub_relu_sync_deprecated.md) overloads incorrectly called the non-synchronous implementation under the 2201 architecture.
- Fixed the issue where the synchronous overload of [asc_rsqrt](../../SIMD-API/c_api/vector_compute/vector_arith/asc_rsqrt.md) incorrectly called the non-synchronous implementation under the 2201 architecture.
- Fixed the issue where [asc_init](../../SIMD-API/c_api/utils/sys_init/asc_init.md) did not fully reset the `CTRL`, Mask, data movement loop, Padding, and data movement atomic operation type states under the 3510 architecture, preventing residual states left by preceding operators from affecting the current operator.
- Fixed the issue where the incorrect field order of `l1_width` and `l1_height` in [asc_l13d_fmatrix_config](../../SIMD-API/c_api/defs/union/asc_l13d_fmatrix_config.md) caused the configured values to differ from expectations.
- Fixed the issue where some 3510 implementations of [asc_copy_gm2l1](../../SIMD-API/c_api/cube_datamove/asc_copy_gm2l1/asc_copy_gm2l1.md) and [asc_copy_l0c2l1](../../SIMD-API/c_api/cube_datamove/asc_copy_l0c2l1/asc_copy_l0c2l1.md) were missing parameters when calling the underlying CCE instructions.
- Corrected the spelling of `ASC_C_API_DEFAULIT_OFFSET` to `ASC_C_API_DEFAULT_OFFSET` in the scalar move-out implementation.
- Fixed the issue where `asc_bfloat162half_rn` and `asc_bfloat162half_rn_sat` used an incorrect rounding mode, correcting the underlying `vcvt` rounding mode from `ROUND_C` to `ROUND_R`.
