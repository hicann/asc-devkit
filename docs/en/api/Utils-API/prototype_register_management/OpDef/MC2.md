# MC2<a name="ZH-CN_TOPIC_0000002114052025"></a>

## Description<a name="zh-cn_topic_0000001935420684_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section36583473819"></a>

Registers this operator as a communication-computation fusion operator. After this API is called, an [OpMC2Def](../OpMC2Def/OpMC2Def.md) structure is returned, through which the communicator name can be configured subsequently.

## Prototype<a name="zh-cn_topic_0000001935420684_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section13230182415108"></a>

```
OpMC2Def &MC2(void)
```

## Parameters<a name="zh-cn_topic_0000001935420684_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section75395119104"></a>

None

## Return Value<a name="zh-cn_topic_0000001935420684_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section25791320141317"></a>

[OpMC2Def](../OpMC2Def/OpMC2Def.md) structure, through which the communicator name can be configured subsequently.

## Constraints<a name="zh-cn_topic_0000001935420684_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section19165124931511"></a>

A custom operator project generated with an older version of the CANN package (without MC2 support) is incompatible with the MC2 API. When using a custom operator project generated by a CANN package other than the current version, pay special attention to compatibility issues. You can check whether the current project supports this feature by checking whether the _build_mc2_ctx field exists in the cmake/util/ascendc_impl_build.py file. If the field is not found, you need to regenerate the custom operator project to enable the MC2 feature.
