# OutputShapeDependOnCompute<a name="ZH-CN_TOPIC_0000002114097069"></a>

<!-- md-trans-meta sourceCommit=3ee506c06c64594337c3b6b8c8af85192bd95f75 translatedAt=2026-09-06T11:34:37.545Z pushedAt=2026-09-11T03:37:20.566Z -->

## Description<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section36583473819"></a>

Identifies whether the output shape of an operator depends on computation. For some operators, such as NonZero (which counts the number of non-zero values in a tensor), the output shape cannot be known before the computation is complete and can only be obtained after the operator computation finishes. When defining the prototype of such operators, use the **OutputShapeDependOnCompute** API to identify them, and write the actual output shape into the output parameter in the operator kernel function, so that the framework can manage the output memory based on this information. For the corresponding kernel-side implementation, see [Kernel-side implementation of operators whose output shape depends on computation](https://gitcode.com/cann/asc-devkit/blob/9.1.0/docs/en/guide/programming_guide/advanced_programming/aclnn_operator_development/kernel_side_operator_implementation.md).

## Prototype<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section13230182415108"></a>

```
OpParamDef &OutputShapeDependOnCompute()
```

## Parameters<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section75395119104"></a>

None

## Return Value<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section25791320141317"></a>

**OpParamDef** operator definition. For details about **OpParamDef**, see [OpParamDef](OpParamDef.md).

## Constraints<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section19165124931511"></a>

-   It can only be used to identify the operator output.
-   A custom operator project generated based on an earlier CANN package (which does not support the **OutputShapeDependOnCompute** feature) is incompatible with the **OutputShapeDependOnCompute** API. When using a custom operator project generated by a non-current CANN package, pay special attention to compatibility issues. You can check whether the output\_shape\_depend\_on\_compute field exists in cmake/util/ascendc\_impl\_build.py in the custom operator project. If the field is not found, regenerate the custom operator project to enable the **OutputShapeDependOnCompute** feature.

## Example<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001575944081_section320753512363"></a>

```
this->Input("x1")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT, ge::DT_FLOAT})
    .Format({ge::FORMAT_ND, ge::FORMAT_ND});
this->Input("x2")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT, ge::DT_FLOAT})
    .Format({ge::FORMAT_ND, ge::FORMAT_ND});
this->Output("y1")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT, ge::DT_FLOAT})
    .Format({ge::FORMAT_ND, ge::FORMAT_ND})
    .OutputShapeDependOnCompute();
```
