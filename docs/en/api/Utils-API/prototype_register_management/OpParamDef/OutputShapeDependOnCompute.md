# OutputShapeDependOnCompute<a name="ZH-CN_TOPIC_0000002114097069"></a>

<!-- md-trans-meta sourceCommit=12a14b50a4f8b34df0b2db2cb19ae1e957b3bde2 translatedAt=2026-11-10T11:14:23.651Z pushedAt=2026-11-13T08:46:49.456Z nl=2 -->

## Description<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section36583473819"></a>

Indicates whether the output shape of an operator depends on computation. For certain operators, such as NonZero (which counts the number of nonzero values in a tensor), the output shape cannot be known before computation completes and can only be obtained after the operator finishes computing. When defining the prototype of such an operator, use the OutputShapeDependOnCompute API to mark it, and write the actual output shape into the output parameter in the operator kernel function, so that the framework side can manage output memory based on this information. For the corresponding kernel function implementation, see [Kernel Implementation for Operators Whose Output Shape Depends on Computation](../../../../guide/programming_guide/advanced_programming/aclnn_operator_development/design_and_implementation/kernel_output_shape_computation.md).

## Prototype<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section13230182415108"></a>

```
OpParamDef &OutputShapeDependOnCompute()
```

## Parameters<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section75395119104"></a>

None

## Return Value<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section25791320141317"></a>

OpParamDef operator definition. For details about OpParamDef, see [OpParamDef](OpParamDef.md).

## Constraints<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001525424352_section19165124931511"></a>

-   It can only be used to identify the operator output.
-   A custom operator project generated based on an earlier CANN package (which does not support the OutputShapeDependOnCompute feature) is incompatible with the OutputShapeDependOnCompute API. When using a custom operator project generated by a CANN package of a different version, pay special attention to compatibility issues. You can check whether the current project supports this feature by checking whether the output_shape_depend_on_compute field exists in cmake/util/ascendc_impl_build.py under the custom operator project. If the field is not found, regenerate the custom operator project to enable the OutputShapeDependOnCompute feature.

## Examples<a name="zh-cn_topic_0000002009944386_zh-cn_topic_0000001526594958_zh-cn_topic_0000001575944081_section320753512363"></a>

```
this->Input("x1")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT, ge::DT_FLOAT})
    .Format({ge::FORMAT_ND, ge::FORMAT_ND});
this->Input("x2")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT, ge::DT_FLOAT})
    .Format({ge::FORMAT_ND, ge::FORMAT_ND});
this->Output("y1")
    .ParamType(REQUIRED)
    .DataType({ge::DT_FLOAT, ge::DT_FLOAT})
    .Format({ge::FORMAT_ND, ge::FORMAT_ND})
    .OutputShapeDependOnCompute();
```
