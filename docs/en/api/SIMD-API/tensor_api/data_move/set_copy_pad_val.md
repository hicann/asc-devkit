## Function Description

The header file path is `tensor_api/tensor.h`.

Sets the constant padding value used for aligned copy from Global Memory to Unified Buffer. This configuration affects subsequent aligned copies that meet the conditions.

## Prototype

```cpp
template <typename T>
__aicore__ inline void set_copy_pad_val(T pad_value)
```

## Parameters

**Table 1** Parameters

| Parameter | Input/Output | Description |
| :--- | :--- | :--- |
| pad_value | Input | Constant padding value, of type `T`. |

## Data Type

`T` supports `int8_t`, `uint8_t`, `int16_t`, `uint16_t`, `half`, `bfloat16_t`, `int32_t`, `uint32_t`, and `float`.

## Return Value

None

## Constraints

- This API takes effect only on the AIV.
- This API only sets the padding value. You must call this API first, and then perform the corresponding [GM to UB copy](../reg_vector_compute/vector_compute_load/copy_gm_to_ub.md).
- The padding value is used for the left and right padding regions and the 32-byte alignment padding region generated by the [GM to UB copy](../reg_vector_compute/vector_compute_load/copy_gm_to_ub.md).
- The padding value configuration affects all subsequent GM to UB aligned copies that meet the conditions until this API is called again to overwrite the configuration. If different padding values are required for different copy tasks, call this API again to set the value before calling the copy API.
- In the `gm_to_ub_params` parameter of the [GM to UB copy](../reg_vector_compute/vector_compute_load/copy_gm_to_ub.md), when both `left_padding_count` and `right_padding_count` are 0, the value configured with this API is used to pad the padding region only when `enable_constant_pad` is `true`. When it is `false`, the hardware automatically pads dummy data, and the value set by this API does not take effect.
- In the `gm_to_ub_params` parameter of the [GM to UB copy](../reg_vector_compute/vector_compute_load/copy_gm_to_ub.md), when `left_padding_count` or `right_padding_count` is not 0, `enable_constant_pad` does not take effect, and you must call this API to configure the padding value before the copy. The left and right padding regions and the region padded on the right side for 32-byte alignment all use this value.

## Example

The following example reads 32 rows of 24 int8_t data per row from Global Memory, pads 3 elements on the left and 5 elements on the right of each row with -9, and then writes the result to Global Memory. The example shows how set_copy_pad_val works with gm_to_ub_params, and uses a mutex to serialize the GM to UB and UB to GM pipeline stages.

```cpp
#include <cstdint>

#include "tensor_api/tensor.h"

constexpr uint32_t rows = 32;
constexpr uint32_t source_columns = 24;
constexpr uint32_t padded_columns = 32;
constexpr uint32_t padded_length = rows * padded_columns;
constexpr uint8_t left_padding = 3;
constexpr uint8_t right_padding = 5;
constexpr int8_t padding_value = -9;
constexpr uint8_t buffer_lock_id = 0;

__global__ __vector__ void padded_copy_kernel(__gm__ int8_t* src, __gm__ int8_t* dst)
{
    using namespace asc::te;
    __ubuf__ int8_t dst_buffer[padded_length];

    auto src_layout = make_frame_layout<nd_ext_layout_ptn, layout_trait_default<int8_t>>(rows, source_columns);
    auto dst_layout = make_frame_layout<nd_ext_layout_ptn, layout_trait_default<int8_t>>(rows, padded_columns);
    auto src_gm = make_tensor(make_mem_ptr<location::gm>(src), src_layout);
    auto dst_ub = make_tensor(make_mem_ptr(dst_buffer), dst_layout);
    auto dst_gm = make_tensor(make_mem_ptr<location::gm>(dst), dst_layout);

    set_copy_pad_val<int8_t>(padding_value);
    constexpr gm_to_ub_params padding_params{left_padding, right_padding, true};

    mutex<pipe_t::PIPE_MTE2> copy_in_mutex(buffer_lock_id);
    copy_in_mutex.lock();
    copy(make_copy(copy_gm_to_ub{}).with(padding_params), dst_ub, src_gm);
    copy_in_mutex.unlock();

    mutex<pipe_t::PIPE_MTE3> copy_out_mutex(buffer_lock_id);
    copy_out_mutex.lock();
    copy(make_copy(copy_ub_to_gm{}), dst_gm, dst_ub);
    copy_out_mutex.unlock();
}
```
