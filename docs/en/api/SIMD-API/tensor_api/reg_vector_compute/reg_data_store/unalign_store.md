## Function Description

The header file path is `"tensor_api/experimental/arch/vector/reg_data_store.h"`, and the namespace is `asc::te::experimental`.

`unalign_store` is used to consecutively evict data in [reg_tensor](../reg_tensor/reg_tensor.md) to a Unified Buffer (UB) address that is not 32-byte aligned. The object internally maintains a non-aligned eviction register and provides the following two operations:

- `store`: Consecutively evicts the first `count` elements of the source register. The formed 32-byte aligned main block is written to UB, and the non-aligned tail block is temporarily stored in the object's internal non-aligned register for concatenation with the next consecutive eviction.
- `flush`: Writes the tail block temporarily stored in the non-aligned register to UB. This API must be called to complete the finalization after a consecutive eviction sequence ends.

`store` uses `src.reg` and ignores `src.mask`. The number of valid evicted elements is specified by `count`; `mask` cannot be used in place of `count`. This API does not automatically advance the destination Tensor or coordinates. The caller must specify the next consecutive write address based on the accumulated number of evicted elements.

## Prototype

```cpp
struct unalign_store {
    __simd_callee__ unalign_store() = default;

    template <typename Tensor, typename RegDataType>
    __simd_callee__ inline void store(
        Tensor dst_tile, const reg_tensor<RegDataType>& src, uint32_t count);

    template <typename Tensor, typename Coord, typename RegDataType>
    __simd_callee__ inline void store(
        Tensor dst_tile, const Coord& coord,
        const reg_tensor<RegDataType>& src, uint32_t count);

    template <typename Tensor>
    __simd_callee__ inline void flush(Tensor dst_base, int32_t coord);
};
```

## Parameters

**Table 1** Template parameter description

| Parameter | Description |
| --- | --- |
| Tensor | Destination Tensor type, automatically deduced from the function argument, which must reside in UB. |
| Coord | Destination Tensor coordinate type of `store`, automatically deduced from the function argument. |
| RegDataType | Source register element type, automatically deduced from the function argument. Except for `int4b_t`, which maps to `int4x2_t`, it must be consistent with the destination Tensor element type. |

**Table 2** Parameters

| Parameter | Input/Output | Description |
| --- | --- | --- |
| dst_tile | Output | Destination Tensor of the current eviction. When no coordinate is passed, the write address is `dst_tile.engine().begin().get()`. The Tensor view is passed by value and does not modify the caller's view, but writes to the UB it points to. |
| coord (store) | Input | Coordinate of the start element of the current eviction in the logical layout of `dst_tile`. The actual write address is `(dst_tile.data() + dst_tile.layout()(coord)).get()`. |
| src | Input | Source `reg_tensor`. `reg` must be initialized, and `mask` does not participate in the eviction. |
| count | Input | Number of elements evicted in the current eviction, of type `uint32_t`, not exceeding the number of elements that a single vector register can hold. |
| dst_base | Output | Destination Tensor used for finalization, whose start address is the actual write address of the first `store` in this consecutive eviction sequence. |
| coord (flush) | Input | Of type `int32_t`, the element offset passed to the underlying finalization API. It should be the sum of all `count` values in this consecutive eviction sequence. It is neither a logical coordinate generated by `make_coord` nor a byte offset. |

The finalization address used by `flush` is determined by `dst_base.engine().begin().get()` and the element offset `coord`. If the first `store` specifies a non-zero coordinate, the Tensor view corresponding to that coordinate should be used as `dst_base`; the un-offset original Tensor cannot be directly used together with the total number of elements in this sequence for finalization.

## Return Value

Neither `store` nor `flush` returns a value.

## Constraints

- The destination address does not need to be 32-byte aligned, but it must satisfy the alignment requirement of the element type, and the actual write range must not exceed the valid UB space.
- The same `unalign_store` object must be reused within a single consecutive eviction sequence, and the element type of all destination tensors must be consistent.
- The actual write addresses of two adjacent `store` operations must be consecutive; that is, the next start address equals the previous start address plus the length of the evicted data. If the addresses are not consecutive, call `flush` on the current sequence first, and then start a new eviction sequence.
- After all `store` operations of each sequence are complete, call `flush` once using the `dst_base` corresponding to the first write address and the accumulated number of evicted elements. The finalization must not be omitted, and `flush` must not be called before any `store` operation has been performed.
- `count` must not exceed the capacity of one register; for example, for `uint8_t` it is `VL / sizeof(uint8_t)` elements, and for `float` it is `VL / sizeof(float)` elements.
- The coordinate dimensions of `store` must match the tensor layout, and the coordinates must not go out of bounds; the element offset and final address of `flush` must be within the valid range.

## Example

The following example consecutively copies `uint8_t` data, with the last segment controlling the number of valid evicted elements through `count`. Both the source and destination tensors are one-dimensional UB tensors, and the start address may be non-32-byte aligned; `total_elements` is greater than 0 and does not exceed the upper limit of `int32_t`. The source UB space must reserve valid space for the last complete VL read and the prefetch cache, and the destination UB space must cover all written data.

```cpp
#include "tensor_api/tensor.h"
#include "tensor_api/experimental/vector_ops.h"

template <typename SrcTensor, typename DstTensor>
__simd_vf__ inline void CopyUnaligned(
    SrcTensor src, DstTensor dst, uint32_t total_elements)
{
    constexpr uint32_t elements_per_register = asc::te::get_vf_len() / sizeof(uint8_t);
    asc::te::experimental::unalign_load loader;
    asc::te::experimental::unalign_store storer;
    loader.prepare(src);
    for (uint32_t offset = 0; offset < total_elements; offset += elements_per_register) {
        uint32_t remaining = total_elements - offset;
        uint32_t count = remaining < elements_per_register ? remaining : elements_per_register;
        auto coord = asc::te::make_coord(offset);
        auto value = loader.load(src, coord);
        storer.store(dst, coord, value, count);
    }
    storer.flush(dst, static_cast<int32_t>(total_elements));
}
```
