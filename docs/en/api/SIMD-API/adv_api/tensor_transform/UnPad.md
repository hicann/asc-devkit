## Description

Performs unpad along the width direction on a two-dimensional Tensor of height \* width. If the Tensor width is not 32B-aligned, this API does not support unpad. The specific functional scenarios of this API are as follows: when the Tensor width is already 32B-aligned, taking half as an example, a 16\*16 Tensor becomes 16\*15 after UnPad.

## Prototype

Because the internal implementation of this API involves complex computation, additional temporary space is required to store intermediate variables during the computation. To obtain the temporary space size **BufferSize**, use the **GetUnPadMaxMinTmpSize** API provided in [UnPad Tiling](UnPad-Tiling.md) to obtain the required maximum and minimum temporary space sizes. The minimum space ensures functional correctness, while the maximum space is used to improve performance.

The temporary space supports two methods: **allocated by the API framework** and **passed in by the developer through the sharedTmpBuffer input parameter**. Therefore, the UnPad API has two prototypes:

-   Pass in the temporary space through the sharedTmpBuffer input parameter

    ```
    template <typename T>
    __aicore__ inline void UnPad(const LocalTensor<T>& dstTensor, const LocalTensor<T>& srcTensor, UnPadParams& unPadParams, LocalTensor<uint8_t>& sharedTmpBuffer, UnPadTiling& tiling)
    ```

    In this method, the developer needs to apply for and manage the temporary memory space, and reuse this part of memory after the API call is completed. The memory is not repeatedly applied for and released, which provides higher flexibility and higher memory utilization.

-   The API framework allocates the temporary space

    ```
    template <typename T>
    __aicore__ inline void UnPad(const LocalTensor<T>& dstTensor, const LocalTensor<T>& srcTensor, UnPadParams& unPadParams, UnPadTiling& tiling)
    ```

    In this method, the developer does not need to apply for the space, but needs to reserve the size of the temporary space.

## Parameters

**Table 1** Template parameters

| Parameter | Description |
| --- | --- |
| T | Data type of the operand. The supported data types are: int16_t, uint16_t, half, int32_t, uint32_t, float. |

| Parameter | Input/Output | Description |
| --- | --- | --- |
| dstTensor | Output | Destination operand, whose shape is two-dimensional. For the definition of the LocalTensor data structure, see [LocalTensor](../../basic_api/data_structures/LocalTensor/LocalTensor.md).<br><br>The type is [LocalTensor](../../basic_api/data_structures/LocalTensor/LocalTensor.md), and the supported TPosition is VECIN/VECCALC/VECOUT. |
| srcTensor | Input | Source operand, whose shape is two-dimensional. For the definition of the LocalTensor data structure, see [LocalTensor](../../basic_api/data_structures/LocalTensor/LocalTensor.md).<br><br>The type is [LocalTensor](../../basic_api/data_structures/LocalTensor/LocalTensor.md), and the supported TPosition is VECIN/VECCALC/VECOUT. |
| UnPadParams | Input | Detailed parameters of UnPad, of the UnPadParams data type. The definition of the UnPadParams structure is shown in the following code, and the specific structure parameters are described as follows:<br>leftPad, the amount of data to unpad on the left. leftPad must be less than 32B. Unit: column. Currently not effective.<br>rightPad, the amount of data to unpad on the right. rightPad must be less than 32B and greater than 0. Unit: column. Currently, unpad is supported only on the right. |
| sharedTmpBuffer | Input | Shared buffer, used to store temporary data generated by the internal computation of the API. In this method, the developer can manage the sharedTmpBuffer memory space and reuse this part of memory after the API call is completed. The memory is not repeatedly applied for and released, which provides higher flexibility and higher memory utilization. For how to obtain the shared buffer size, see [UnPad Tiling](UnPad-Tiling.md).<br><br>The type is [LocalTensor](../../basic_api/data_structures/LocalTensor/LocalTensor.md), and the supported TPosition is VECIN/VECCALC/VECOUT. |
| tiling | Input | Tiling information required for computation. For how to obtain the Tiling information, see [UnPad Tiling](UnPad-Tiling.md). |

```
struct UnPadParams {
    uint16_t leftPad = 0;
    uint16_t rightPad = 0;
};
```

None

## Examples

In this example, the width of the Tensor is already 32B-aligned. Taking half as an example, such as 16\*16, UnPad is performed to obtain 16\*15. The input data type is half.

```
// dstLocal: output Tensor
// srcLocal: Input Tensor.
// unPadParams: Parameters that control padding removal.
AscendC::UnPadParams unPadParams{0, 1}; // Remove 0 columns from the left and 1 column from the right. Left unpad is currently not supported.
AscendC::UnPad(dstLocal, srcLocal, unPadParams, tilingData.unpadTilingData);
```
