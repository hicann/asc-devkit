# MatmulConfig

<!-- md-trans-meta sourceCommit=754fb95859dead826727a591e674261c6a829a08 translatedAt=2026-10-08T12:43:09.376Z pushedAt=2026-10-26T13:18:46.540Z -->

**MatmulConfig** is a template parameter used to configure Matmul template information and related configuration parameters. If it is not configured, the **Norm** template is enabled by default. For details about the **Norm** template, see [Table 1](#template-features). For the parameter description of **MatmulConfig**, see [Table 2](#matmulconfig-params). **MatmulConfig** can be defined in the following ways:

-   This template parameter can select one of the provided templates. The value range of the currently provided **MatmulConfig** templates is [CFG\_NORM, CFG\_MDL, CFG\_IBSHARE\_NORM, MM\_CFG\_BB], corresponding to the default **Norm**, **MDL**, **IBShare**, and **BasicBlock** templates, respectively. For details about each template, see [Table 1](#template-features).
-   Based on various template acquisition APIs, this template parameter can be customized to configure the template parameters and obtain a custom template. The template acquisition APIs include [GetNormalConfig](GetNormalConfig.md), [GetMDLConfig](GetMDLConfig.md), [GetSpecialMDLConfig](GetSpecialMDLConfig.md), [GetIBShareNormConfig](GetIBShareNormConfig.md), and [GetBasicConfig](GetBasicConfig.md).
-   In addition, **MatmulConfig** can be split into the secondary sub-Configs [MatmulShapeParams](GetMMConfig.md#table16317184295116), [MatmulQuantParams](GetMMConfig.md#table8313111211573), [MatmulBatchParams](GetMMConfig.md#table15129204644), and [MatmulFuncParams](GetMMConfig.md#table66217141862). By using the [GetMMConfig](GetMMConfig.md) API to set the required secondary sub-Configs and [MatmulConfigMode](GetMMConfig.md#table17837129144319), you can obtain a custom template parameter configuration for **MatmulConfig** more flexibly.

**Table 1** Template features

<a id="template-features"></a>

| Template | Implementation | Advantages | Recommended use scenario |
| --- | --- | --- | --- |
| Norm | Supports caching multiple base blocks in L1. **MTE2** transfers base blocks from GM to L1 in multiple passes, one base block per pass, and the transferred base blocks are not cleared. (Example: [depthA1](../Matmul_Tiling/TCubeTiling_struct.md#deptha1)=6 in the **Tiling** structure means that six A-cube base blocks are transferred to L1, one base block per pass, and **MTE2** performs six transfers.) | The **MTE1** pipeline can be started in advance (because the operations after **MTE1** can be performed once one base block is transferred). | The **Norm** template is enabled by default. |
| MDL, SpecialMDL | Supports caching multiple base blocks in L1. **MTE2** transfers data from GM to L1 in a single "bulk" transfer. (Example: [depthA1](../Matmul_Tiling/TCubeTiling_struct.md#deptha1)=6 in the **Tiling** structure means that six A-cube base blocks are transferred to L1 at once, and **MTE2** performs one transfer.) For the differences between the **MDL** and **SpecialMDL** templates, see [Table 2](#matmulconfig-params). | For general large-shape scenarios, this reduces the repeated transfers of **MTE2** and improves performance. | Large-shape scenarios. |
| IBShare | In MIX scenarios, when the GM addresses of the A cube or B cube are the same, **MTE2** transfers are reduced by sharing the L1 buffer. | Reduces **MTE2** transfers and improves performance. | In MIX scenarios, the GM addresses of the A cube or B cube of multiple AIVs are the same.<br><br>Note: The **IBShare** template requires that the A/B cubes reused by multiple AIVs be fully loaded into the L1 buffer. |
| BasicBlock | In scenarios without tail blocks, when the base block size is determined, the input base block size is configured through the [GetBasicConfig](GetBasicConfig.md) API to fix the cube size transferred by **MTE1** each time and the cube size computed in each cube multiplication, thereby reducing the parameter computation overhead. | Reduces the parameter computation overhead during **MTE1** cube transfer and cube multiplication computation. | No tail blocks, and the base block (baseM, baseN) size is determined. |
| SpecialBasicBlock | In scenarios without tail blocks, when the base block size and the shape within a single core are determined, the **MatmulConfig** parameters are configured to further eliminate the header overhead **Scalar** computation on the basis of the **BasicBlock** template. | Reduces the parameter computation overhead during **MTE1** cube transfer and cube multiplication computation, and further eliminates the header overhead **Scalar** computation. | Without tail blocks, the sizes of the base block (baseM, baseN) and the shape within a single core (singleCoreM, singleCoreN) are determined.<br><br>Note: In the same scenario, it is recommended to use [constantization](GetMatmulApiTiling.md) to obtain better performance benefits. |
