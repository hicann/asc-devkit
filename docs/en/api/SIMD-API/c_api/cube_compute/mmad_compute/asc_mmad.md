## Description

The header file path is: `"c_api/cube_compute/cube_compute.h"`.

This interface is the core Cube Multiply-Accumulate (Mmad) computation interface of Ascend C for Ascend AI chips, designed specifically for high-performance operator development. It encapsulates the cube multiply-accumulate computation capability of Ascend NPU hardware and is widely used in the development of neural network layers (such as fully connected layers and convolution layers) and numerical computation operators. Its calculation formula is as follows:

$$
C_{M \times N} = A_{M \times K} \times B_{K \times N} + C_{M \times N}
$$

Here, A, B, and C are the left cube, right cube, and result cube, respectively. The C cube can be initialized as an all-zero cube, a cube in the L0C Buffer, or a Bias cube by configuring the parameters of this interface. The information of each cube is described in the following table:

<!-- npu="950" id8 -->
**Table** Cube information description ([NPU Architecture Version 3510](../../../../../guide/programming_guide/language_extension/simd_builtin_keywords.md))

| Cube | Storage Location | Shape (rows × columns) | Data Format | Fractal Size (rows × columns) |
| --- | --- | --- | --- | --- |
| A | L0A Buffer | M×K | Nz | 16×K0 |
| B | L0B Buffer | K×N | Zn | K0×16 |
| C | L0C Buffer | M×N | Nz | 16×16 |
| Bias (used for C cube initialization) | BiasTable Buffer | 1×N, broadcast-copied to M rows to initialize the C cube when used | ND | - |

In the table, the value of K0 is `32B / sizeof(dtype)`, where `dtype` is the data type of the cube.
<!-- end id8 -->

<!-- npu="A3,910b" id9 -->
**Table** Cube information description ([NPU Architecture Version 2201](../../../../../guide/programming_guide/language_extension/simd_builtin_keywords.md))

| Cube | Storage Location | Shape | Data Format | Fractal Size |
| --- | --- | --- | --- | --- |
| A | L0A Buffer | M×K | Zz | 16×K0 |
| B | L0B Buffer | K×N | Zn | K0×16 |
| C | L0C Buffer | M×N | Nz | 16×16 |
| Bias (used for C cube initialization) | BiasTable Buffer | 1×N, broadcast-copied to M rows to initialize the C cube when used | ND | - |

In the table, the value of K0 is `32B / sizeof(dtype)`, where `dtype` is the data type of the cube. In particular, when the data type is `int4b_t`, `K0 = 64`.
<!-- end id9 -->

This interface is a cube computation interface and takes effect only on the AIC.

For the layout of the input cube and the Bias cube, see [Key Fractal Format Details](../cube_compute_fractal_intro/key_fractal_format_details.md) and [Auxiliary Cube Fractal Format Details](../cube_compute_fractal_intro/aux_cube_fractal_format_details.md), respectively. For the connection among data preparation, computation, and result move-out, see [Cube Computation Flow](../overview.md#cube-computation-flow).

For the computation mode and precision description of FP32 input, see [HF32](../mmad_compute_key_features/HF32.md). The switch is controlled by [asc_enable_hf32](../mmad_compute_aux_config/asc_enable_hf32.md) and [asc_disable_hf32](../mmad_compute_aux_config/asc_disable_hf32.md).

## Return Value

## Pipeline Type

PIPE_M

## Constraints

- This interface takes effect only on the AIC. Calling it on the AIV returns directly.
- When any one of `m`, `k`, and `n` is 0, the interface is treated as a NOP (no operation).

- Memory usage constraint description:
  <!-- npu="950" id10 -->
  - For Ascend 950PR&950DT products:

      - The L0C Buffer size is 256KB, and the L0A Buffer and L0B Buffer sizes are both 64KB. The BiasTable Buffer size is 4KB. The start address and occupied space of a cube must not exceed the range of the corresponding buffer.
      - The start address of each cube must meet the alignment requirements in [Parameter Description](#asc_mmad_param_table). For other address constraints of the operands, see [Storage Unit Description](../../general_description_and_constraints.md#storage-unit-description).
      - When applying for cube storage space, use the values padded according to the fractal size: M and N are each padded up to a multiple of 16, and K is padded up to a multiple of K0, where K0 is `32B / sizeof(dtype)` and `dtype` is the data type of the cube. `m`, `k`, and `n` still pass in the valid M, K, and N values of the cube. The padded part is invalid data and does not participate in the computation of the valid region of the result cube.
      - When M is 1 and `disable_gemv` is false, the GEMV mode is enabled. In this case, cube A is read from the L0A Buffer in the ND format, cube A must be arranged in the ND format, and the start address must still be aligned to 512 bytes.
  <!-- end id10 -->

  <!-- npu="A3,910b" id11 -->
  - For the following product models:

 	  <!-- npu="A3" id16 -->
    Atlas A3 products
 	  <!-- end id16 -->
 	  <!-- npu="910b" id17 -->
 	  Atlas A2 products
 	  <!-- end id17 -->
 	  The L0C Buffer size is 128KB, and the L0A Buffer and L0B Buffer sizes are both 64KB. The BiasTable Buffer size is 1KB. The start address and occupied space of the cube must not exceed the range of the corresponding Buffer.
 <!-- end id11 -->

- Synchronization constraint description:

  For the scenario where the input cube is computed in blocks along the K axis and the results are accumulated into the same L0C Buffer block, when `(m / 16) * (n / 16) < 10`, you need to call [asc_sync_pipe](../../sync/intra_core_sync/asc_sync_pipe.md) between two adjacent cube multiply-accumulate instructions, and set the input parameter `pipe` to `PIPE_M`.

- UnitFlag constraint description:

  - When UnitFlag is enabled, the cube multiply-accumulate instruction and the corresponding cube move-out instruction must enable UnitFlag at the same time. When you want the same L0C Buffer memory space to be continuously operated only by multiple cube multiply-accumulate instructions or multiple cube move-out instructions, all instructions except the last one must set `unit_flag_mode` to `asc_unit_flag_mode::ENABLE_KEEP` to maintain the continuous occupied state of the operated memory space, and the last instruction must set it to `asc_unit_flag_mode::ENABLE_UPDATE` to release the occupied state.
  - When UnitFlag is enabled, the cube computation direction must be consistent with the cube move-out read order. When the cube move-out instruction enables Nz2ND inline format conversion, or when inline format conversion is not performed but B8/B4 quantization is enabled and the Channel Merge function is triggered, call [asc_set_mmad_direction_n](../mmad_compute_aux_config/asc_set_mmad_direction_n.md); in other scenarios, call [asc_set_mmad_direction_m](../mmad_compute_aux_config/asc_set_mmad_direction_m.md).
  - When UnitFlag is enabled, it is recommended that the computation data size of the cube multiply-accumulate be consistent with the data size of the cube move-out. Inconsistency between the two may cause execution exceptions. When you need to clear the residual state generated by UnitFlag, you can call [asc_set_l0c_copy_config](../../cube_datamove/cube_store_aux_config/asc_set_l0c_copy_config.md), set `enable_unit_flag` to true, set the element flag bits of all memory blocks in the L0C Buffer to 0, and disable UnitFlag.

- Special value/boundary value constraint description:

  When the floating-point input or output contains inf/nan, you can configure the CTRL\[48\] bit of the CTRL register through the [asc_set_ctrl](../../spr/asc_set_ctrl.md) interface to control the computation mode:

  - When set to 0, the saturation mode is used, where inf output is saturated to ±MAX and nan output is saturated to 0;
  - When set to 1, the non-saturation mode is used, where inf/nan keeps the original output.

  Note that nan input should be avoided, otherwise an execution error may occur; integer types support only the saturation mode.

The following call example code is supported only by the Ascend 950PR&950DT products.

```cpp
#include <cstdint>
#include <iostream>
#include <vector>
#include "c_api/asc_simd.h"
#include "acl/acl.h"

namespace {
constexpr uint32_t M = 48;
constexpr uint32_t K = 96;
constexpr uint32_t N = 80;
constexpr uint32_t CUBE_M = 16;
constexpr uint32_t CUBE_K = 32;

__global__ __cube__ void asc_mmad_kernel(__gm__ int8_t* a, __gm__ int8_t* b, __gm__ int32_t* output)
{
    asc_init();
    __cbuf__ int8_t a_l1[M * K];
    __cbuf__ int8_t b_l1[N * K];
    __ca__ int8_t a_l0[M * K];
    __cb__ int8_t b_l0[N * K];
    __cc__ int32_t c_l0[M * N];

    asc_set_gm2l1_nz_para(1, 1, M, 0);
    asc_copy_gm2l1_nd2nz(
        a_l1, a, K, asc_load_l2_cache_mode::NORMAL_FIRST_VICTIM, M, K, 0, false);
    asc_set_gm2l1_nz_para(1, 1, N, 0);
    asc_copy_gm2l1_nd2nz(
        b_l1, b, K, asc_load_l2_cache_mode::NORMAL_FIRST_VICTIM, N, K, 0, false);
    asc_sync_notify(PIPE_MTE2, PIPE_MTE1, EVENT_ID0);
    asc_sync_wait(PIPE_MTE2, PIPE_MTE1, EVENT_ID0);
    asc_copy_l12l0a(a_l0, a_l1, 0, 0, M / CUBE_M, K / CUBE_K, M / CUBE_M, M / CUBE_M);
    asc_copy_l12l0b(b_l0, b_l1, 0, 0, N / CUBE_M, K / CUBE_K, N / CUBE_M, N / CUBE_M);
    asc_sync_notify(PIPE_MTE1, PIPE_M, EVENT_ID0);
    asc_sync_wait(PIPE_MTE1, PIPE_M, EVENT_ID0);
    asc_mmad(c_l0, a_l0, b_l0, M, K, N, asc_unit_flag_mode::DISABLE, true, false, true);
    asc_sync_notify(PIPE_M, PIPE_FIX, EVENT_ID0);
    asc_sync_wait(PIPE_M, PIPE_FIX, EVENT_ID0);
    asc_set_l0c_copy_nz_para(1, 0, 0);
    asc_copy_l0c2gm(output, c_l0, N, M, N, M, asc_store_l2_cache_mode::NORMAL_FIRST_VICTIM,
        asc_unit_flag_mode::DISABLE, asc_quant_mode::NoQuant, asc_relu_pre_mode::NONE, false, true, false, false);
    asc_sync();
}

template <typename T>
void print_row(const char* label, const std::vector<T>& data)
{
    std::cout << label << ':';
    for (uint32_t i = 0; i < 8; ++i) std::cout << ' ' << +data[i];
    std::cout << " ..." << std::endl;
}
} // namespace

int main()
{
    // Store B in GM as N x K. After moving it into L0B, form the K x N cube required by MMAD.
    std::vector<int8_t> a(M * K), b(N * K);
    std::vector<int32_t> output(M * N), golden(M * N);
    for (uint32_t row = 0; row < M; ++row) {
        for (uint32_t k = 0; k < K; ++k) {
            a[row * K + k] = static_cast<int8_t>(static_cast<int32_t>((row + 2 * k) % 5) - 2);
        }
    }
    for (uint32_t col = 0; col < N; ++col) {
        for (uint32_t k = 0; k < K; ++k) {
            b[col * K + k] = static_cast<int8_t>(static_cast<int32_t>((3 * col + k) % 7) - 3);
        }
    }
    for (uint32_t row = 0; row < M; ++row) {
        for (uint32_t col = 0; col < N; ++col) {
            for (uint32_t k = 0; k < K; ++k) {
                golden[row * N + col] += a[row * K + k] * b[col * K + k];
            }
        }
    }

    aclInit(nullptr);
    aclrtSetDevice(0);
    int8_t *a_device = nullptr, *b_device = nullptr;
    int32_t* output_device = nullptr;
    aclrtMalloc(reinterpret_cast<void**>(&a_device), a.size(), ACL_MEM_MALLOC_HUGE_FIRST);
    aclrtMalloc(reinterpret_cast<void**>(&b_device), b.size(), ACL_MEM_MALLOC_HUGE_FIRST);
    aclrtMalloc(reinterpret_cast<void**>(&output_device), output.size() * sizeof(int32_t), ACL_MEM_MALLOC_HUGE_FIRST);
    aclrtMemcpy(a_device, a.size(), a.data(), a.size(), ACL_MEMCPY_HOST_TO_DEVICE);
    aclrtMemcpy(b_device, b.size(), b.data(), b.size(), ACL_MEMCPY_HOST_TO_DEVICE);
    asc_mmad_kernel<<<1, 0>>>(a_device, b_device, output_device);
    aclrtSynchronizeDevice();
    aclrtMemcpy(output.data(), output.size() * sizeof(int32_t), output_device, output.size() * sizeof(int32_t),
        ACL_MEMCPY_DEVICE_TO_HOST);
    print_row("Input A row 0", a);
    print_row("Input B row 0", b);
    print_row("Output row 0", output);
    print_row("Golden row 0", golden);
    const bool passed = output == golden;
    std::cout << (passed ? "[Success] asc_mmad passed." : "[Failed] asc_mmad failed.") << std::endl;
    aclrtFree(a_device);
    aclrtFree(b_device);
    aclrtFree(output_device);
    aclrtResetDevice(0);
    aclFinalize();
    return passed ? 0 : 1;
}
```
