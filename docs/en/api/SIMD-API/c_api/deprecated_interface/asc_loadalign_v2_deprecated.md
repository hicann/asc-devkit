## Description

The header file path is: `"c_api/reg_compute/load/loadalign.h"`.

**This API is deprecated. For asc_loadalign_brc_v2, use [asc_loadalign_brc_datablock](../reg_compute/load/asc_loadalign_brc_datablock.md); for asc_loadalign_brc_v3, use [asc_loadalign_brc_elem2datablock](../reg_compute/load/asc_loadalign_brc_elem2datablock.md); for asc_loadalign_unpack_v2, use [asc_loadalign_unpack4](../reg_compute/load/asc_loadalign_unpack4.md) to implement this function.**

Aligned data load API that loads data from Unified Buffer (UB) into the destination operand in a continuous aligned manner. It supports multiple load modes. The API passes the offset through an address register, and the user can choose to update the offset or update the address of the source operand.

- UNPACKV2 load mode: Unpack mode. Loads VL/4-length data as unsigned integer u8, unpacks it to VL-length u32 type, and pads the intermediate positions with 0.
- BRCV2 load mode: Reads one DataBlock (32B) and broadcasts it to VL.
- BRCV3 load mode: Loads (VL/DataBlock) B of data and broadcasts each element (16bit/32bit) into one DataBlock (32B).

## Parameters

**Table 1** Parameter description

| Parameter | Input/Output | Description |
| :----- | :------- | :------- |
| dst | Output | Destination operand (vector data register). |
| src | Input | Source operand, the 32B-aligned start address in UB. |
| offset | Input | Address register, which must be generated through the [asc_update_addr_reg](../reg_compute/reg_addr_reg/asc_update_addr_reg.md) interface and is used to record the offset relative to the start address of `src`, in units of element count. |

For details about vector data registers and address registers, see [reg data type definition](../defs/type/data_type_definition.md).

## Return Value

None

## Pipeline Type

PIPE_V

## Constraints

- The src in this interface must be 32B-aligned.

__ubuf__ int8_t* src = (__ubuf__ int8_t*)asc_get_phy_buf_addr(0);
