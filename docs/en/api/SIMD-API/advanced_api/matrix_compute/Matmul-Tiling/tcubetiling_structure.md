# TCubeTiling Structure

<!-- md-trans-meta sourceCommit=2bc2b38d5648dc61f632186b01ba7f36c2295b13 translatedAt=2026-09-09T07:37:08.973Z pushedAt=2026-09-12T09:55:18.221Z -->

The TCubeTiling structure contains the parameters related to the Matmul tiling algorithm. It is passed to the Matmul kernel side and used for the tiling, data movement, and computation of Matmul. For the parameter description of the TCubeTiling structure, see [Table 1](#tcubetiling-struct).


<a id="tcubetiling-struct"></a>
**Table 1**  TCubeTiling structure description
| Parameter | Data Type | Description |
| --- | --- | --- |
| usedCoreNum | int | Number of AI Cores used. Set it based on the actual situation. Value range: [1, maximum number of AI Cores]. The relationship between this parameter and the shape-related parameters is: usedCoreNum = (M / singleCoreM) * (N / singleCoreN). |
| M, N, Ka, Kb | int | Shape size of the original input of matrices A, B, and C, in elements. M and Ka are the Shape of the original input of matrix A, and Kb and N are the Shape of the original input of matrix B.<br>Size constraints:<br>Except for Ascend 950PR/Ascend 950DT, the following scenarios require enabling the [intrinsicsCheck](../Matmul-Kernel/MatmulConfig.md#matmulconfig-params) parameter in MatmulConfig to complete the Matmul computation.<br>If matrix A is in ND format and is not transposed, enable the intrinsicsCheck parameter when Ka is greater than 65535; M has no size limit. If it is transposed, enable the intrinsicsCheck parameter when M is greater than 65535; Ka has no size limit.<br>If matrix B is in ND format and is not transposed, enable the intrinsicsCheck parameter when N is greater than 65535; Kb has no size limit. If it is transposed, enable the intrinsicsCheck parameter when Kb is greater than 65535; N has no size limit.<br><br>Alignment constraints:<br>If matrix A is input in NZ format, M must be aligned to 16 elements and Ka must be aligned to C0_size. If matrix B is input in NZ format, Kb must be aligned to C0_size and N must be aligned to 16 elements.<br>If matrices A and B are in ND format, there is no alignment constraint.<br><br>Note: For NZ format input, C0_size is 8 for the float data type, 16 for the half/bfloat16_t data type, 32 for the int8_t/fp8_e4m3fn_t/fp8_e5m2_t/hifloat8_t data type, and 64 for the int4b_t/fp4x2_e2m1_t/fp4x2_e1m2_t data type. |
| singleCoreM, singleCoreN, singleCoreK | int | Shape size of matrices A, B, and C within a single core, in elements. This parameter value must be greater than 0.<br><br>singleCoreK = K, and K is not split during multi-core processing; singleCoreM <= M; singleCoreN <= N.<br><br>Note: If matrix A is input in NZ format, singleCoreM must be aligned to 16 elements and singleCoreK must be aligned to C0_size. If matrix B is input in NZ format, singleCoreK must be aligned to C0_size and singleCoreN must be aligned to 16 elements. |
| baseM, baseN, baseK<a name="p17899165811566"></a> | int | Shape size of matrices A, B, and C participating in one matrix multiplication instruction, in elements.<br><br>The shape size of matrices A, B, and C participating in one matrix multiplication must be aligned by fractal. For details, see the data format description in [Mmad](../../../basic_api/cube_compute_ISASI/mmad_compute/Mmad.md).<br><br>Note: This parameter value must be greater than 0. In the MxMatmul scenario, baseK must be a multiple of 64. |
| depthA1, depthB1 | int | Number of fully loaded basic blocks in A1 and B1. depthA1 is the number of fully loaded baseM * baseK blocks in A1, and depthB1 is the number of fully loaded baseN * baseK blocks in B1.<br><br>Note: This parameter value must be greater than 0. |
| stepM, stepN, stepKa, stepKb<a name="p139009583566"></a> | int | stepM is the multiple of baseM in the M direction of the buffer where the left matrix is cached in A1.<br><br>stepN is the multiple of baseN in the N direction of the buffer where the right matrix is cached in B1.<br><br>stepKa is the multiple of baseK in the Ka direction of the buffer where the left matrix is cached in A1.<br><br>stepKb is the multiple of baseK in the Kb direction of the buffer where the right matrix is cached in B1.<br><br>Note: This parameter value must be greater than 0. |
| isBias<a name="p2051215216314"></a> | int | Whether to enable Bias. The parameter values are as follows:<br>0: Bias is not enabled (default value). 1: Bias is enabled.<br><br>Note: This parameter does not support values other than the above. When set to other values, the parameter behavior is undefined. |
| transLength | int | max(A1Length, B1Length, C1Length, BiasLength), where A1Length, B1Length, C1Length, and BiasLength represent the UB space sizes that matrices A/B/C/Bias need to temporarily occupy during computation. |
| iterateOrder | int | One Iterate computes a C matrix tile of size [baseM, baseN]. After the Iterate is complete, Matmul automatically offsets the position of the C matrix output by the next Iterate. iterOrder indicates the order of the automatic offset. The parameter values are as follows:<br>0: Offset in the M-axis direction first and then in the N-axis direction. 1: Offset in the N-axis direction first and then in the M-axis direction.<br><br>Note: This parameter does not support values other than the above. When set to other values, the parameter behavior is undefined. |
| dbL0A, dbL0B,<br><br>dbL0C | int | Whether MTE1 enables double buffer.<br><br>dbL0A: Whether the left matrix MTE1 enables double buffer. dbL0B: Whether the right matrix MTE1 enables double buffer. dbL0C: Whether MMAD enables double buffer. The parameter values are as follows:<br>1: Double buffer is not enabled. 2: Double buffer is enabled.<br><br>Note: This parameter does not support values other than the above. When set to other values, the parameter behavior is undefined. |
| shareMode | int | This parameter is reserved, and you do not need to pay attention to it. |
| shareL1Size | int | This parameter is reserved, and you do not need to pay attention to it. |
| shareL0CSize | int | This parameter is reserved, and you do not need to pay attention to it. |
| shareUbSize | int | This parameter is reserved, and you do not need to pay attention to it. |
| batchM | int | This parameter is reserved, and you do not need to pay attention to it. |
| batchN | int | This parameter is reserved, and you do not need to pay attention to it. |
| singleBatchM | int | This parameter is reserved, and you do not need to pay attention to it. |
| singleBatchN | int | This parameter is reserved, and you do not need to pay attention to it. |
| mxTypePara | int | Combined parameter used in the MxMatmul scenario, indicating the multiple of the size of scaleA/scaleB loaded into L1 relative to the size of matrices A/B loaded into L1. The details are as follows:<br>Bits 0 to 6 indicate the scale factor of the data size loaded in the K direction between scaleA and matrix A, scaleFactorKa, that is, scaleFactorKa = data size of scaleA loaded in the K direction / data size of matrix A loaded in the K direction, with a data range of [1, 127];<br>Bits 8 to 14 indicate the scale factor of the data size loaded in the K direction between scaleB and matrix B, scaleFactorKb, that is, scaleFactorKb = data size of scaleB loaded in the K direction / data size of matrix B loaded in the K direction, with a data range of [1, 127];<br>Bits 16 to 22 indicate the scale factor of the data size loaded in the M direction between scaleA and matrix A, scaleFactorM, that is, scaleFactorM = data size of scaleA loaded in the M direction / data size of matrix A loaded in the M direction, with a data range of [1, 127];<br>Bits 24 to 30 indicate the scale factor of the data size loaded in the N direction between scaleB and matrix B, scaleFactorN, that is, scaleFactorN = data size of scaleB loaded in the N direction / data size of matrix B loaded in the N direction, with a data range of [1, 127];<br><br>Note:<br>For the scaleA matrix, multi-fold loading in the M direction is supported only when the Ka direction is fully loaded. That is, scaleFactorM can be set to a value greater than 1 only when baseK * stepKa * scaleFactorKa >= singleCoreK.<br>For the scaleB matrix, multi-fold loading in the N direction is supported only when the Kb direction is fully loaded. That is, scaleFactorN can be set to a value greater than 1 only when baseK * stepKb * scaleFactorKb >= singleCoreK.<br>The data size loaded in the M, N, and K directions for scaleA and scaleB cannot exceed the actual size.<br>This parameter takes effect only in the MDL template. |

In most cases, you obtain the TCubeTiling structure by calling the [GetTiling](GetTiling.md) API. For details, see [usage instructions](matmul_tiling_class_usage.md). If you customize the TCubeTiling parameters, the value of each parameter must satisfy the corresponding parameter constraints in [Table 1](#tcubetiling-struct) and [Table 2](#table1275812182115). If you need to modify and adjust the tiling after obtaining the TCubeTiling structure by calling the [GetTiling](GetTiling.md) API, set the parameters by referring to the following TCubeTiling parameter constraints and recommended values for performance tuning.

-   TCubeTiling parameter constraints

    A set of valid TCubeTiling parameters must satisfy all constraints in [Table 2](#table1275812182115) simultaneously. If the MatmulConfig template of the Matmul object is the [MDL template](../Matmul-Kernel/MatmulConfig.md#table6981133810309), in addition to [Table 2](#table1275812182115), the parameters must also satisfy [Table 3 MDL template supplementary constraints](#table1094616401179).

    **Table 2**  TCubeTiling constraints

    <a name="table1275812182115"></a>
    | Constraint | Description |
    | --- | --- |
    | usedCoreNum <= aiCoreCnt | The number of cores used is less than or equal to the maximum number of cores of the current AI processor. |
    | baseM * baseK * sizeof(A_type) * dbL0A< l0a_size | The base block of matrix A does not exceed the l0a buffer size. |
    | baseN * baseK * sizeof(B_type) * dbL0B < l0b_size | The base block of matrix B does not exceed the l0b buffer size. |
    | baseM * baseN * sizeof(l0c_type) * dbL0C < l0c_size, where l0c_type is the int32_t or float data type. | The base block of matrix C does not exceed the l0c buffer size. |
    | baseN * sizeof(Bias_type) < biasT_size | The base block of Bias does not exceed the BiasTable buffer size. |
    | stepM * stepKa * db = depthA1<br>    <br>Here, db indicates whether the left matrix MTE2 enables double buffer, that is, whether L1 enables double buffer. The value is 1 (double buffer not enabled) or 2 (double buffer enabled). | The value of depthA1 is the same as stepM * stepKa * db. |
    | stepN * stepKb * db = depthB1<br>    <br>Here, db indicates whether the right matrix MTE2 enables double buffer, that is, whether L1 enables double buffer. The value is 1 (double buffer not enabled) or 2 (double buffer enabled). | The value of depthB1 is the same as stepN * stepKb * db. |
    | The cache block size AL1Size of matrix A on L1 and the cache block size BL1Size of matrix B on L1 must satisfy:<br>    Without bias: AL1Size + BL1Size <= L1_size<br>    <br>    With bias: AL1Size + BL1Size + baseN * sizeof(Bias_type) <= L1_size<br>    <br>    AL1Size and BL1Size are computed as follows:<br>Transposed scenario:<br>AL1Size = CeilDiv(baseM, C0_size) * baseK * depthA1 * sizeof(A_type)<br>   BL1Size = baseN * baseK * depthB1 * sizeof(B_type)<br><br>    Non-transposed scenario:<br>AL1Size = baseM * baseK * depthA1 * sizeof(A_type)<br> BL1Size = CeilDiv(baseN, C0_size)* baseK * depthB1 * sizeof(B_type) | The cache blocks of matrices A, B, and Bias on L1 satisfy the L1 buffer size limit;<br>    <br>Note: C0_size is 8 for the float data type, 16 for the half/bfloat16_t data type, 32 for the int8_t/fp8_e4m3fn_t/fp8_e5m2_t/hifloat8_t data type, and 64 for the int4b_t/fp4x2_e2m1_t/fp4x2_e1m2_t data type. |
    | baseM * baseK, baseK * baseN, and baseM * baseN are aligned by fractal in NZ format. | The base blocks of matrices A, B, and C must satisfy the alignment constraints:<br>    baseM and baseN must be aligned to 16 elements; in the scenario where matrix A is not transposed and matrix B is transposed, baseK must be aligned to C0_size; in other scenarios (matrix A transposed or matrix B not transposed), baseK is aligned to 16 elements;<br>    <br>Note: C0_size is 8 for the float/int32_t data type, 16 for the half/bfloat16_t data type, 32 for the int8_t/fp8_e4m3fn_t/fp8_e5m2_t/hifloat8_t data type, and 64 for the int4b_t/fp4x2_e2m1_t/fp4x2_e1m2_t data type. |
    | In the MxMatmul scenario, if the positions of matrices A and B are both GM, there is no special restriction on singleCoreK. In this case, if the K-direction size of scaleA and scaleB (that is, Ceil(singleCoreK, 32)) is odd, you need to pad the K direction of scaleA and scaleB with 0 to an even number; for other combinations of the logical positions of matrices A and B, that is, when the positions of matrices A and B are not both GM, the value of singleCoreK rounded up to 32 elements must be an even multiple of 32;<br>    <br>When the input data type is fp4x2_e2m1_t/fp4x2_e1m2_t, the inner axis must be even. | The data type of scaleA/scaleB is fp8_e8m0_t, and the K direction must be 2-byte contiguous. The K direction of scaleA/scaleB is 1/32 of the K direction of matrices A/B; when the positions of matrices A and B are not both GM, the value of singleCoreK rounded up to 32 elements must be an even multiple of 32.<br>    <br>In the MxMatmul scenario, when the input data type is fp4x2_e2m1_t/fp4x2_e1m2_t, the minimum unit for computation is 8 bytes, and two 4-byte elements need to be combined into one 8-byte unit for computation, so the inner axis must be even. |

    **Table 3** MDL template supplementary constraints

    <a name="table1094616401179"></a>
    | Constraint | Description |
    | --- | --- |
    | When Ka is not fully loaded, that is, Ka / baseK > stepKa, stepM = 1 | When the K direction is not fully loaded, the M direction can only be moved block by block. |

-   Recommended values for performance tuning

    Based on tiling tuning experience, the following values or value-taking approaches are recommended for some TCubeTiling parameters:

    -   Recommended base block \(baseM, baseN, baseK\): \(128, 256, 64\)
    -   dbL0A / dbL0B = 2
    -   depthA1 / \(stepM \* stepKa\) = 2
    -   depthB1 / \(stepN \* stepKb\) = 2
    -   Set the stepKa/stepKb parameters first so that the K direction is fully loaded, and then consider full loading in the M direction or N direction.
