# Improving Efficiency with Short Vector Types

<!-- md-trans-meta sourceCommit=e3c8c70b3f5d27f3770063ae4b535bc75d904e3e translatedAt=2026-08-26T14:46:09.060Z -->

[Priority] Medium

[Description] In SIMT programming mode, short vector types are used instead of common data types to improve operator execution efficiency. The AI processor accesses the L2 cache with a 128-byte cache line. When processing a data type that occupies two bytes of memory, the effective data volume of a single warp performing coalesced access to contiguous data is only 64 bytes, which does not reach the data length of a single cache line, resulting in a bandwidth utilization of 50%. By using short vector types for data transfer and computation, a single coalesced access by the threads within each warp can cover the entire cache line, utilizing 100% of the bandwidth and significantly improving overall memory access efficiency.

[Example Introduction] Take the [vector addition operator](https://gitcode.com/cann/asc-devkit/tree/9.1.0/examples/03_simt_api/03_best_practices/00_memory_optimizations/short_vector_add) as an example. The input data is of the half type, and the calculation formula is $z_i = x_i + y_i$. The data scale is 64×256×1024 elements. The operator is configured with 64 thread blocks, each containing 1024 threads, for a total of 65536 threads, with each thread processing 256 elements. Under the same configuration, the half2 short vector type is used to process the input data, with each thread processing 128 elements.

  [Negative Example] The half type is used for element-by-element computation, and the cache line is not fully occupied.

   **Figure 1** Bandwidth diagram of half type computation

   ![img](../../../figures/half_bandwidth.png "half type single-warp bandwidth")

  ```cpp
  template<typename T>
  __global__ void add(T* x, T* y, T* z, uint64_t size)
  {
      int32_t stride = gridDim.x * blockDim.x;
      for (int32_t idx = blockIdx.x * blockDim.x + threadIdx.x; idx < size; idx += stride) {
          z[idx] = x[idx] + y[idx];
      }
  }
  ```

  In the preceding implementation, because the scalar half (2B) data type is used, the width of the physically contiguous address request generated by the coalesced access of a single warp (32 threads) is only 64B, and the 128B cache line is not fully occupied.

  [Positive Example] Use the half2 type for computation to improve bandwidth utilization.

  **Figure 2** Bandwidth diagram of half2 type computation

  ![img](../../../figures/half2_bandwidth.png "Short vector bandwidth diagram")
  ```cpp
  template<typename T, typename U>
  __global__ void add2(T* x, T* y, T* z, uint64_t size)
  {
      // Convert to the vector type
      const U* x2 = reinterpret_cast<const U*>(x);
      const U* y2 = reinterpret_cast<const U*>(y);
      U* z2 = reinterpret_cast<U*>(z);

      uint64_t vectorSize = size / 2;
      int32_t stride = gridDim.x * blockDim.x;

      // Process even pairs in a short vector loop
      for (int32_t idx = blockIdx.x * blockDim.x + threadIdx.x; idx < vectorSize; idx += stride) {
          z2[idx] = x2[idx] + y2[idx];
      }
      // Process the last odd element
      if (blockIdx.x == 0 && threadIdx.x == 0 && (size % 2 != 0)) {
          uint64_t lastIdx = size - 1;
          z[lastIdx] = x[lastIdx] + y[lastIdx];
      }
  }
  ```

  In the preceding implementation, the half type is promoted to the 4-byte half2 type for computation. The amount of data written by a single warp in a single write reaches `32 * 4B = 128B`, which exactly covers one cache line.

  On the Ascend 950PR product, the performance data after using the half2 type is as follows:

  **Optimization Effect Analysis**:

  - **End-to-end duration**: reduced from 86.478 μs to 45.371 μs, a decrease of 47.5%, with overall performance improved by 1.91x.
  - **Total AI vector cycles**: reduced from 8,832,432 to 4,584,309, a decrease of 48.1%, proving that the number of issued instructions has been streamlined.
  - **Main memory read/write bandwidth**: read bandwidth increased from 7.77 GB/s to 14.51 GB/s, an improvement of 86.7%; write bandwidth increased from 6.24 GB/s to 7.25 GB/s, an improvement of 16.2%.

  **Extended Scenarios**

  Short vector types are not limited to half2. [Summary] In SIMT operators, by leveraging [short vector data types](../../../../api/SIMT-API/SIMT_programming_intro/extended_syntax/built_in_data_types_139.md#short-vector-type), the bandwidth utilization of a single Warp can reach 100%, while the number of issued instructions is streamlined, significantly improving overall memory access efficiency.
