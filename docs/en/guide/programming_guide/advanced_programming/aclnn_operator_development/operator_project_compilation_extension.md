# Operator Project Compilation Extension<a name="ZH-CN_TOPIC_0000002453850485"></a>

<!-- md-trans-meta sourceCommit=d0ede7621d11bdc88cdafb221560ec6e0bfe996d translatedAt=2026-08-26T11:54:03.486Z pushedAt=2026-09-03T06:30:20.759Z -->

When you create an operator project using the msOpGen tool, the related compilation scripts are fixed locally. To use new features provided by the operator project (for example, MC2 operator support), you need to run the msOpGen tool again to regenerate the project. To avoid frequent project rebuilding caused by feature updates, the cmake scripts of the operator project are packaged into the CANN software package. You can use find\_package to locate the corresponding cmake modules package, and then use the cmake function APIs provided by the operator project.

With this development method, you can organize the operator project by yourself by referring to the following project directory. The directory structure is similar to that generated by msOpGen, but you no longer need to create the **cmake** and **scripts** directories, which are packaged into the CANN software package. Taking the AddCustom operator as an example, the directory structure is as follows:

```
AddCustom
├── CMakeLists.txt              // Top-level CMakeLists.txt of the operator project
├── CMakePresets.json           // Compilation configuration items, a built-in cmake feature. cmake 3.19 or later is required to use this feature.
├── framework                   // Directory for operator plugin implementation files during AI framework adaptation
├── op_host                     // Host-side implementation files
│   ├── add_custom.cpp         // Files for operator prototype registration, shape inference, tiling implementation, and other content
│   ├── add_custom_tiling.h    // Operator tiling definition file
│   └── CMakeLists.txt         // Host-side CMakeLists file
├── op_kernel                   // Kernel-side implementation file
│   ├── Add
│   │   ├── add_custom.cpp    // Operator code implementation file
└   └── CMakeLists.txt         // Kernel-side CMakeLists file
```

## Writing CMakeLists.txt<a name="section1323123615016"></a>

-   Top-level **CMakeLists.txt** of the operator project

    1.  Use **find\_package** to locate the required compilation library.
    2.  Use **npu\_op\_package** to set the compilation output form of the operator project. RUN, SHARED, and STATIC are supported, corresponding to the operator run package form, operator dynamic library form, and operator static library form, respectively. In addition, this API can configure the content of the package (that is, the compilation artifact) and the installation location of the package.
    3.  Add the subdirectories to be compiled.

    ```
    cmake_minimum_required(VERSION 3.16.0)            # Specify the minimum required CMake version.
    project(opp)
    # 1. Use find_package to locate the required compilation library.
    # ${ASCEND_CANN_PACKAGE_PATH} is the path of the CANN package, which developers can use directly.
    find_package(ASC REQUIRED HINTS ${ASCEND_CANN_PACKAGE_PATH}/compiler/tikcpp/ascendc_kernel_cmake)
    # 2. Use npu_op_package to set the compilation output form of the operator project.
    set(package_name ${vendor_name})
    npu_op_package(${package_name}                     # package name
                                                       # In RUN mode, this name is used to name the directory after operator deployment. In static library mode, the output is lib${package_name}.a.
        TYPE RUN                                       # Specify the compilation output type, [RUN|STATIC|SHARED]
        CONFIG
            ENABLE_SOURCE_PACKAGE True                 # Whether to package the source code into the run package
            ENABLE_BINARY_PACKAGE True                 # Whether to compile the Kernel binary. In SHARED/STATIC mode, this must be set to True. Defaults to True
            INSTALL_PATH ${CMAKE_BINARY_DIR}/          # Installation location of the package
    )
    #3. Add the subdirectories to be compiled.
    if(EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/op_host)
        add_subdirectory(op_host)                      # Add the op_host subdirectory for compilation
    endif()
    if(EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/op_kernel)
        add_subdirectory(op_kernel)                    # Add the op_kernel subdirectory for compilation
    endif()
    ```

-   Host-side **CMakeLists.txt**

    1.  Use **npu\_op\_code\_gen** to generate the aclnn single-operator call code, the prototype definition code required for graph compilation, and so on.
    2.  In the single-operator call scenario, use **npu\_op\_library** to compile the aclnn single-operator call library.
    3.  In the operator graph compilation scenario, use **npu\_op\_library** to compile the operator prototype library required for graph compilation.
    4.  Use **npu\_op\_library** to compile the tiling-related library.
    5.  Use **npu\_op\_package\_add** to add the preceding host-side libraries to the corresponding package.

    ```
    aux_source_directory(${CMAKE_CURRENT_SOURCE_DIR} ops_srcs)
    #1. Use npu_op_code_gen to generate the aclnn single-operator call code, the prototype definition code required for graph compilation, and so on.
    npu_op_code_gen(
         SRC ${ops_srcs}                                                           # Set of host-side implementation files
         PACKAGE ${package_name}                                                   # Corresponds to package_name of npu_op_package
         COMPILE_OPTIONS -g                                                        # Compile option
         OUT_DIR ${ASCEND_AUTOGEN_PATH}                                            # Specify the path for saving the generated files
         JOIN_OP_DEF False    # Optional parameter, defaults to False. When set to False, compile the operators corresponding to the AI processor type set in CMakePreset.json. When set to True, compile the operators corresponding to the AI processor type common to both CMakePreset.json and the operator prototype registration.
    )
    #2. In the single-operator call scenario, use npu_op_library to compile the aclnn single-operator call library.
    file(GLOB autogen_aclnn_src ${ASCEND_AUTOGEN_PATH}/aclnn_*.cpp)                # Add the aclnn-related source files generated by npu_op_code_gen to the source file list.
                                                                                   
    set_source_files_properties(${autogen_aclnn_src} PROPERTIES GENERATED TRUE)    # Set the corresponding file properties to files generated during compilation.
    npu_op_library(cust_opapi ACLNN                                                # Specify the library name and type, and the source files involved in compilation.
         ${autogen_aclnn_src}
    )
    target_compile_options(cust_opapi PRIVATE                                      # Add compile options for the corresponding library, consistent with the general cmake syntax.
         -fvisibility=hidden
    )
    
    #3. In the operator graph compilation scenario, use npu_op_library to compile the operator prototype library required for graph compilation.
    file(GLOB proto_src ${ASCEND_AUTOGEN_PATH}/op_proto.cc)                        # Add the prototype definition-related source files generated by npu_op_code_gen to the source file list.
    set_source_files_properties(${proto_src} PROPERTIES GENERATED TRUE)            # Set the corresponding file properties to files generated during compilation.
    npu_op_library(cust_op_proto GRAPH                                             # Specify the library name and type, and the source files involved in compilation.
         ${ops_srcs}
         ${proto_src}
    )
    target_compile_options(cust_op_proto PRIVATE                                   # Add compile options for the corresponding library, consistent with the general cmake syntax.
         -fvisibility=hidden
    )
    
    #4. Use npu_op_library to compile the tiling-related library.
    file(GLOB fallback_src ${ASCEND_AUTOGEN_PATH}/fallback_*.cpp)                  # Add the Tiling-related source files generated by npu_op_code_gen to the source file list.
                                                                                   # This file is generated if the operator has EnableFallBack configured.
    set_source_files_properties(${fallback_src} PROPERTIES GENERATED TRUE)         # Set the corresponding file properties to files generated during compilation.
    npu_op_library(cust_optiling  TILING                                           # Specify the library name and type, and the source files involved in compilation.
         ${ops_srcs}
         ${fallback_src}
    )
    target_compile_options(cust_optiling PRIVATE                                   # Add compile options for the corresponding library, consistent with the general cmake syntax.
         -fvisibility=hidden
    )
    
    #5. Use npu_op_package_add to add the host-side libraries above to the corresponding package.
    npu_op_package_add(${package_name}                                             # Corresponds to package_name of npu_op_package
         LIBRARY                                                                   # Add the host-side related libraries. The library names correspond to the library names in the previous steps.
              cust_optiling
              cust_opapi
              cust_op_proto
    )
    ```

-   Kernel-side **CMakeLists.txt**

    1.  Use **npu_op_kernel_options** to add operator compilation options. For supported compilation options, see [Compilation Options](operator_package_compilation/operator_project_compilation.md#table151052168302).
    2.  Use **npu\_op\_kernel\_sources** to specify the operator-specific directory and source files to compile.
        -   If the operator's source files are not placed directly under the **SRC\_BASE** directory (set through **npu\_op\_kernel\_library**), you can specify a specific directory through **KERNEL\_DIR**.
        -   If the kernel implementation cpp file of the operator needs a custom name, specify both **OP\_TYPE** (operator type) and **KERNEL\_FILE** (kernel implementation cpp file name) to configure the correspondence between them. If not configured, the kernel implementation cpp file name and **OpType** must satisfy the [conversion rule](./operator_prototype_definition.md).

    3.  Use **npu\_op\_kernel\_library** to compile the kernel library.
    4.  Use **npu\_op\_package\_add** to add the preceding kernel-side library to the corresponding package.

    ```
    #1. Use npu_op_kernel_options to add operator compile options.
    npu_op_kernel_options(ascendc_kernels ALL OPTIONS --save-temp-files -g)# Add compile options for the operator
    
    #2. Use npu_op_kernel_sources to specify the operator-specific directory and source files to compile.
    npu_op_kernel_sources(ascendc_kernels                                  # Corresponding kernel library name, consistent with npu_op_kernel_library
        OP_TYPE AddCustom                                                  # If the operator's kernel implementation cpp file requires a custom name, configure the operator type
        KERNEL_DIR ./Add                                                   # Concatenate the KERNEL_DIR directory with the SRC_BASE directory as the directory where the kernel implementation cpp file resides
        COMPUTE_UNIT Ascendxxxyy                                           # Set KERNEL_FILE to take effect on the Ascendxxxyy model
        KERNEL_FILE add_custom.cpp                                         # If the operator's kernel implementation cpp file requires a custom name, configure the kernel implementation cpp file name
    )
    
    #3. Use npu_op_kernel_library to compile the kernel library.
    npu_op_kernel_library(ascendc_kernels                                  # Kernel library name
        SRC_BASE ${CMAKE_SOURCE_DIR}/op_kernel/                            # Specify the root directory of the kernel-side source code
        TILING_LIBRARY cust_optiling                                       # Specify the dependent Tiling library
    )
    #4. Add the kernel-side library to the package
    npu_op_package_add(${package_name}                                     # Corresponds to the package_name of npu_op_package
        LIBRARY ascendc_kernels                                            # Add the kernel-side related library. The library name corresponds to the library name in the preceding step.
    )
    ```

The preceding compilation environment options can be configured in two ways:

-   They can be set directly through the **set** command.

    ```
    # Used directly in CMakeLists.txt
    set(vendor_name "customize")
    set(ASCEND_COMPUTE_UNIT "ascendxxxyy")
    ```

-   Set through **CMakePresets.json**. If this method is used, cmake 3.19 or later must be installed.

    ```
    {
        "version": 1,
        "cmakeMinimumRequired": {
            "major": 3,
            "minor": 19,
            "patch": 0
        },
        "configurePresets": [
            {
                "name": "default",
                "displayName": "Default Config",
                "description": "Default build using Unix Makefiles generator",
                "generator": "Unix Makefiles",
                "binaryDir": "${sourceDir}/build_out",
                "cacheVariables": {
                    "ASCEND_COMPUTE_UNIT": {
                        "type": "STRING",
                        "value": "ascendxxxyy"
                    },
                    "vendor_name": {
                        "type": "STRING",
                        "value": "customize"
                    }
                }
            }
        ]
    }
    ```

    Then use the following command to build, which performs compilation according to the preset specified by **--preset**.

    ```
    // cmake build and compilation in the Shell environment
    cmake -S . -B build_out --preset=default // Search for CMakePresets.json in the current directory (.)
    // If the user's cmake version is earlier than 3.19.0, the --preset build option is not supported. In this case, use the following build and compilation command.
    Replace ${INSTALL_DIR} with the file storage path after CANN software installation. Taking installation as the root user as an example, the default file storage path after installation is: /usr/local/Ascend/cann.
    opts=$(python3 $INSTALL_DIR/tools/tikcpp/ascendc_kernel_cmake/fwk_modules/util/preset_parse.py $script_path/CMakePresets.json)
    cmake -S . -B "$BUILD_DIR" $opts
    ```

## Compilation Command Description<a name="section15466121132213"></a>

When the package type is configured as RUN, compile the project by referring to the following compilation command, which uses the cmake pack capability to generate a run package.

```
# Run the command in the project root directory.
mkdir -p build_out
rm -rf build_out/*
cmake -S . -B build_out --preset=default
cmake --build build_out --target binary -j$(nproc)
cmake --build build_out --target package -j$(nproc)
```

When the package type is configured as **SHARED** or **STATIC**, compile the project by referring to the following compilation command:

```
# Run the command in the project root directory.
mkdir -p build_out
rm -rf build_out/*
cmake -S . -B build_out --preset=default
cmake --build build_out --target binary -j$(nproc)
cmake --build build_out --target install -j$(nproc)
```

1.  <a name="li030816192116"></a>npu\_op\_package

    Creates a package.

    ```
    npu_op_package(<package_name> TYPE <type> [CONFIG] [ENABLE_SOURCE_PKG <value>] [ENABLE_BINARY_PACKAGE <value>] [INSTALL_PATH <path>])
    ```

    The parameter description is as follows:

    -   **<package\_name\>**: required, name of the package.
    -   **TYPE <type\>**: required, type of the package. The value is **RUN**, **SHARED**, or **STATIC**, corresponding to the operator run package form, operator dynamic library form, and operator static library form, respectively.
    -   **\[CONFIG\]**: optional, used to configure the content and installation location of the package.
        -   **\[ENABLE\_SOURCE\_PKG <value\>\]**: optional, specifies whether to package the source code into the package. The default value is **True**.
        -   **\[ENABLE\_BINARY\_PACKAGE <value\>\]**: optional, specifies whether to package the binary files into the package. The default value is **True**.
        -   **\[INSTALL\_PATH <path\>\]**: optional, specifies the installation path of the package. The default value is **CMAKE\_BINARY\_DIR**.
        -   **\[ENABLE\_CPACK <value\>\]**: optional, specifies whether to package. The default value is **True**. For scenarios where users need to customize packaging, it can be set to **False**. When configured as **False**, compilation outputs are generated directly in the **<path\>** directory and are not packaged into a run package.

2.  <a name="li1671193919294"></a>npu\_op\_package\_add

    Adds targets or files to the package.

    ```
    # Add targets.
    npu_op_package_add(<package_name> LIBRARY <target_name1> [<target_name2>...] ) 
    # Add files, used only in run package mode.
    npu_op_package_add(<package_name> FILES <file_name1> [<file_name2>...] [TYPE <target_type>] [PACKAGE_PATH <pkg_path>])
    ```

    The parameter description is as follows:

    -   **<package\_name\>**: required, name of the package.
    -   **LIBRARY**: required, specifies the name of the target to be added to the package.
        -   **<target\_name1\> \[<target\_name2\>...\]**: required, list of target names.

    -   **FILES**: required, specifies the name of the file to be added to the package.
        -   **<file\_name1\> \[<file\_name2\>...\]**: required, list of file names.

    -   **\[TYPE <target\_type\>\]**: optional, specifies the file type and installs the file to the corresponding directory. The value is **ACLNN** or **GRAPH**. When configured as **ACLNN**, the file is packaged to the directory where the single-operator call header files are located under the **aclnn** directory of the run package. When configured as **GRAPH**, the file is packaged to the directory where the operator prototype definition header files required for graph compilation are located under the run package.
    -   **\[PACKAGE\_PATH <pkg\_path\>\]**: optional, specifies the relative path of the file in the package. The **TYPE** and **PACKAGE\_PATH** parameters are mutually exclusive, that is, only one of them can be configured.

3.  <a name="li25281233402"></a>npu\_op\_library

    Creates a host-side library.

    ```
    npu_op_library(<library_name> TYPE <library_type> <files>) 
    ```

    The parameter description is as follows:

    -   **<library\_name\>**: required, name of the host-side library.
    -   **TYPE <library\_type\>**: required, type of the host library. The value can be **TILING**, **ACLNN**, **GRAPH**, or **TF\_PLUGIN**.
        -   **TILING**: tiling-related library.
        -   **ACLNN**: aclnn single-operator call library.
        -   **GRAPH**: operator prototype library required for graph compilation.
        -   **TF\_PLUGIN**: library related to TensorFlow framework adaptation.

    -   **<files\>**: required, source files to be compiled.

4.  <a name="li16862112335017"></a>npu\_op\_kernel\_library

    Creates a kernel-side library.

    ```
    npu_op_kernel_library(<target_name> SRC_BASE <path> TILING_LIBRARY <tiling_target>) 
    ```

    The parameter description is as follows:

    -   **<target\_name\>**: required, target name.
    -   **SRC\_BASE <path\>**: required, specifies the base directory of the kernel source code. An absolute path must be configured, for example, the absolute path of the **op\_kernel** directory in the example.
    -   **TILING\_LIBRARY <tiling\_target\>**: required, specifies the dependent tiling target.

5.  <a name="li15612655800"></a>npu\_op\_kernel\_options

    Adds compilation options for the kernel target.

    ```
    npu_op_kernel_options(<target_name> <op_type> [COMPUTE_UNIT <soc_version>] OPTIONS …) 
    ```

    The parameter description is as follows:

    -   **<target\_name\>**: required, target name.
    -   **<op\_type\>**: required, defines the scope where the configuration takes effect. The value is **ALL** or **OP\_TYPE**. **ALL** indicates that the configuration takes effect on all operators, and **OP\_TYPE** indicates that the configuration takes effect on a specific operator.
    -   **\[COMPUTE\_UNIT <soc\_version\>\]**: optional, used to set the compilation options of an operator on a specific AI processor model. If this option is not specified, the configuration takes effect on all models by default.

        >[!NOTE] Note 
        >- For the following products: run the **npu-smi info** command on the server where the AI processor is installed to query and obtain the **Name** information. The actual configuration value is **AscendName**. For example, if the **Name** value is **xxxyy**, the actual configuration value is **Ascendxxxyy**.<br><br>
        >    Atlas A2 training products/Atlas A2 inference products  
        >    Atlas 200I/500 A2 inference products  
        >    Atlas inference products  
        >    Atlas training products<br><br> 
        >- For <term>Atlas A3 training products</term>/<term>Atlas A3 inference products</term>, run the **npu-smi info -t board -i id -c chip_id** command on the server where the AI processor is installed to query and obtain the **Chip Name** and **NPU Name** information. The actual configuration value is **Chip Name_NPU Name**. For example, if the **Chip Name** value is **Ascendxxx** and the **NPU Name** value is **1234**, the actual configuration value is **Ascendxxx_1234**. Where:<br>**id**: device ID. The NPU ID queried through the **npu-smi info -l** command is the device ID.<br> **chip_id**: chip ID. The chip ID queried through the **npu-smi info -m** command is the chip ID.<br><br>
        >- For Ascend 950PR/Ascend 950DT, run the **npu-smi info -t board -i id** command on the server where the AI processor is installed to query and obtain the **Chip Name** and **NPU Name** information. The actual configuration value is **Chip Name_NPU Name**. For example, if the **Chip Name** value is **Ascendxxx** and the **NPU Name** value is **1234**, the actual configuration value is **Ascendxxx_1234**.<br> Where: **id** is the device ID. The NPU ID queried through the **npu-smi info -l** command is the device ID.

    -   **OPTION...**: required, compilation options passed to the compiler.

6.  <a name="li178055111110"></a>npu\_op\_kernel\_sources

    Describes the source information of the kernel target, including setting the kernel implementation file and source path of the operator.

    ```
    npu_op_kernel_sources(<target_name> [OP_TYPE <op_type>] [KERNEL_DIR <path>] [COMPUTE_UNIT <soc_version>] [KERNEL_FILE <file>]) 
    ```

    The parameter description is as follows:

    -   **<target\_name\>**: required, target name.
    -   **\[OP\_TYPE <op\_type\>\]**: optional, operator type, which must coexist with **KERNEL\_FILE**.
    -   **\[KERNEL\_DIR <path\>\]**: optional, specifies the relative path of the kernel source code to **SRC\_BASE**.

        If the operator's source files are not placed flat in the **SRC\_BASE** directory (set through **npu\_op\_kernel\_library**), you can specify a specific directory through **KERNEL\_DIR**.

    -   **\[COMPUTE\_UNIT <soc\_version\>\]**: optional, sets **KERNEL\_FILE** to take effect on the **<soc\_version\>** model. By default, **KERNEL\_FILE** takes effect on all models.
    -   **\[KERNEL\_FILE <file\>\]**: optional, specifies the kernel implementation file name of the operator entry.

        If the kernel implementation cpp file of the operator needs a custom name, specify both **OP\_TYPE** (operator type) and **KERNEL\_FILE** (kernel implementation cpp file name) to configure the correspondence between them. If they are not configured, the kernel implementation cpp file name and **OpType** must satisfy the [conversion rule](./operator_prototype_definition.md).

7.  <a name="li121991221837"></a>npu\_op\_device\_tiling\_library

    Creates a device-side tiling library. When this option is used, the package type can only be configured as **RUN** (run package mode).

    ```
    npu_op_device_tiling_library(<target_name> <type> <files>) 
    ```

    The parameter description is as follows:

    -   **<target\_name\>**: required, target name.
    -   **<type\>**: required, specifies the type of the tiling output. The supported values are **SHARED** and **STATIC**.
    -   **<files\>**: required, specifies the tiling source files.

8.  <a name="li184365230416"></a>npu\_op\_code\_gen

    Executes the code generation process to generate the aclnn single-operator call code and the prototype definition code required for graph compilation.

    ```
    npu_op_code_gen(SRC <src_files> OUT_DIR <output_dir> PACKAGE <pkg_name> [COMPILE_OPTIONS ...] [JOIN_OP_DEF ...])
    ```

    The parameter description is as follows:

    -   **SRC <src\_files\>**: required, scope of source files involved in code generation.
    -   **OUT\_DIR <output\_dir\>**: required, output path of the generated code.
    -   **PACKAGE <pkg\_name\>**: required, specifies the package name of the generated code.
    -   **\[COMPILE\_OPTIONS ...\]**: optional, custom compilation options during compilation.
    -   **\[JOIN\_OP\_DEF ...\]**: optional, defaults to **False**. When set to **False**, compiles the operators corresponding to the AI processor type set in **CMakePreset.json**. When set to **True**, compiles the operators corresponding to the AI processor types common to both **CMakePreset.json** and the operator prototype registration.
