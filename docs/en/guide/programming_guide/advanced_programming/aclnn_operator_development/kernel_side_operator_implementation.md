## Automatically Generating the Kernel-Side Operator Implementation Template<a name="section282118105913"></a>

Implement the kernel function of the operator in the "op\_kernel/xxx.cpp" file under the operator project directory. The kernel function definition template has been automatically generated by the msOpGen tool, as shown in the following example. **Note that the parameters are arranged in the order of "input, output, workspace, tiling". Do not change this order.**

```
#include "kernel_operator.h"
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR workspace, GM_ADDR tiling) {
    GET_TILING_DATA(tiling_data, tiling);// Obtain the tiling parameters. For details, see the following description.
    // TODO: user kernel impl
}
```

>[!NOTE] Note
>If an input and an output in the operator prototype definition have the same name, the output parameter in the automatically generated kernel function is suffixed with "ref" to distinguish them. The following is an example:
>```
>extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR x_ref, GM_ADDR workspace, GM_ADDR tiling) {
>    ...
>}
>```

## Obtaining Tiling Parameters Using GET\_TILING\_DATA<a name="section141061949201"></a>

**GET\_TILING\_DATA** is provided to obtain the tiling information passed into the operator kernel entry function and fill it into the registered tiling structure. This function is compiled through macro expansion. Note that the corresponding operator host implementation must define the TilingData structure, and implement and register the tiling function that computes TilingData. For details, see [Host-side Tiling Implementation](host_tiling_implementation/basic_process.md).

The following is an example of calling [GET\_TILING\_DATA](../../../../api/SIMD-API/basic_api/Kernel-Tiling/GET_TILING_DATA.md) in the kernel function to obtain TilingData:

```
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR workspace, GM_ADDR tiling)
{
    GET_TILING_DATA(tilingData, tiling);
    KernelAdd op;
    op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);
    if (TILING_KEY_IS(1)) {
        op.Process();
    }
}
```

## Obtaining the Data Type and Format of Operator Inputs and Outputs in a Kernel Function<a name="section194927685210"></a>

The operator project provides three macros in the kernel function, **DTYPE\_<Arg\>**, **ORIG\_DTYPE\_<Arg\>**, and **FORMAT\_<Arg\>**, to represent the data type, original data type, and data format of the kernel function input parameters (operator inputs and outputs). **<Arg\>** is the uppercase form of the input parameter.

-   **DTYPE\_<Arg\>**: data type of the input parameter. It is the data type actually usable on the device side, such as half and float.
-   **ORIG\_DTYPE\_<Arg\>**: original data type of the input parameter. It is the data type (excluding the namespace) specified when the prototype is defined on the host side, such as **DT\_FLOAT16** and **DT\_FLOAT**.
-   **FORMAT\_<Arg\>**: data format of the input parameter. It is the data format (excluding the namespace) specified when the prototype is defined on the host side, such as **FORMAT\_ND** and **FORMAT\_NZ**.

The following is an example:

```
template<class T> func() {}
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR workspace, GM_ADDR tiling)
{
    DTYPE_X temp;
    func<DTYPE_Z>();
    if (FORMAT_Y == FORMAT_ND) {
        ...
    }
    if (ORIG_DTYPE_Y == DT_FLOAT) {
        ...
    }
}
```

## Kernel Implementation of Operators Whose Output Shape Depends on Computation<a name="section1961152716108"></a>

For some operators, such as NonZero (which counts the number of non-zero values in a tensor), the output shape cannot be known before the computation is complete and can only be obtained after the operator computation is complete. When defining the prototype of such operators, you need to use the **OutputShapeDependOnCompute** API to identify them, and write the actual output shape to the output parameter in the operator kernel function, so that the framework can manage the output memory based on this information.

Add an output parameter of the **GM\_ADDR** type after all outputs of the kernel function, and write the output shape information to this output parameter after the kernel function computation is complete. The layout format of the shape information is as follows, with a size of **n \* \(8 + 1\)**, and the data type of each element is **uint64\_t**. Here, *n* indicates the number of outputs whose shape information is to be refreshed. For each output, the first element stores the actual shape dimension (dim), and the subsequent eight elements store the shape information of each dimension.

![](../../../figures/pipeline_task_runtime_diagram_33.png)

>[!NOTE] Note
>- The order of outputs is consistent with the order of outputs in the prototype definition.
>- For the uint64\_t output data type (for tensors), set the high bit of the uint32\_t dim to 1, indicating that the tensor is parsed as the uint64\_t type.

-   In the following example, the operator has one output obtained through dependency computation. The data type of the output tensor is uint32\_t. After the computation is complete, the obtained output shape is (32, 64), and the output parameter shape\_out is used to store this shape information, with the value (2, 32, 64). The code example is as follows:

    ```
    extern "C" __global__ __aicore__ void xxx_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR shape_out, GM_ADDR workspace, GM_ADDR tiling) {
    ...
        constexpr uint32_t SHAPEOUT_SIZE = 9;
        // The output data is 2-dimensional ([32, 64]), and the tensor type is uint32_t.
        // shapeoutGlobal_uint32 is used to store the output shape information, and the data type is fixed to uint64_t.
        GlobalTensor<uint64_t> shapeoutGlobal_uint32;
        shapeoutGlobal_uint32.SetGlobalBuffer((__gm__ uint64_t*)shape_out, SHAPEOUT_SIZE);
        shapeoutGlobal_uint32.SetValue(0, 2);
        shapeoutGlobal_uint32.SetValue(1, 32);
        shapeoutGlobal_uint32.SetValue(2, 64);
    ...
    }
    ```

-   In the following example, the operator has one output obtained through dependency computation. The data type of the output tensor is uint64\_t. After the computation is complete, the obtained output shape is (1, 64, 128, 128), and the output parameter shape\_out is used to store this shape information, with the value (0x0000000080000000 | 4 , 1, 64, 128, 128). The code example is as follows:

    ```
    extern "C" __global__ __aicore__ void xxx_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR shape_out, GM_ADDR workspace, GM_ADDR tiling) {
    ...
        constexpr uint32_t SHAPEOUT_SIZE = 9;
        // The output data is 4-dimensional ([1, 64, 128, 128]), and the tensor type is uint64_t.
        // shapeoutGlobal_uint64 is used to store the output shape information, and its data type is fixed to uint64_t.
        GlobalTensor<uint64_t> shapeoutGlobal_uint64;
        shapeoutGlobal_uint64.SetGlobalBuffer((__gm__ uint64_t*)shape_out, SHAPEOUT_SIZE);
        shapeoutGlobal_uint64.SetValue(0, 0x0000000080000000 | 4);
        shapeoutGlobal_uint64.SetValue(1, 1);
        shapeoutGlobal_uint64.SetValue(2, 64);
        shapeoutGlobal_uint64.SetValue(3, 128);
        shapeoutGlobal_uint64.SetValue(4, 128);
    ...
    }
    ```

-   In the following example, the operator has two outputs obtained through dependency computation. The data type of the output tensors is uint64\_t. After the computation is complete, the shapes of the outputs are (16, 32) and (1, 16, 16, 32). The output parameter shape\_out is used to store the shape information. The example is as follows:

    ```
    extern "C" __global__ __aicore__ void xxx_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR shape_out, GM_ADDR workspace, GM_ADDR tiling) {
        ...
        // There are two outputs whose shapes need to be refreshed: one is 2-dimensional [16, 32], and the other is 4-dimensional [1, 16, 16, 32]
        // The output tensor type is uint64_t.
        constexpr uint32_t SHAPEOUT_SIZE_2 = 18;
        // shapeoutGlobal_uint64_2 is used to store the output shape information, and its data type is fixed to uint64_t.
        GlobalTensor<uint64_t> shapeoutGlobal_uint64_2;
        shapeoutGlobal_uint64_2.SetGlobalBuffer((__gm__ uint64_t*)shape_out, SHAPEOUT_SIZE_2 );
        shapeoutGlobal_uint64_2.SetValue(0, 0x0000000080000000 | 2);
        shapeoutGlobal_uint64_2.SetValue(1, 16);
        shapeoutGlobal_uint64_2.SetValue(2, 32);
        // The data at index[3] to index[8] is a placeholder.
        shapeoutGlobal_uint64_2.SetValue(9, 0x0000000080000000 | 4);
        shapeoutGlobal_uint64_2.SetValue(10, 1);
        shapeoutGlobal_uint64_2.SetValue(11, 16);
        shapeoutGlobal_uint64_2.SetValue(12, 16);
        shapeoutGlobal_uint64_2.SetValue(13, 32);
        ...
    }
    ```
