# msobjdump Tool<a name="ZH-CN_TOPIC_0000002028951292"></a>

<!-- md-trans-meta sourceCommit=754fb95859dead826727a591e674261c6a829a08 translatedAt=2026-10-23T14:49:57.115Z pushedAt=2026-11-03T07:05:13.440Z nl=2 -->

This tool mainly provides parsing and extraction for the operator Executable and Linkable Format (ELF) files generated by project compilation, and presents the result information in a readable form, making it convenient for developers to intuitively obtain kernel file information. It currently supports parsing the related artifacts generated by kernel function direct call projects and custom operator projects.

>[!NOTE] Note 
>- An ELF file is a file format used for binary files, executable files, object code, shared libraries, and core dumps, including common \*.a and \*.so files. A typical ELF file consists of the following:
>    - ELF header: describes the overall organization of the file, including the file type, machine type, version number, and other information.
>    - Program header table: describes the information of various segments in the file, including how the program is loaded into memory for execution.
>    - Section header table: describes the information of various sections in the file, including the program's code, data, symbol table, and so on.
>- During tool usage, if the following scenarios occur, analyze and troubleshoot the issue based on the log prompt information.
>    - The ELF file is not found.
>    - ELF file permission error.
>    - ELF file exists but parsing or extraction is not supported.

## Tool Installation<a name="section2423188195113"></a>

1.  Install the msobjdump tool.

    The tool is released with the CANN software package (refer to [Environment Preparation](../../getting_started/environment_setup.md) to complete the CANN installation). Its default path is `${INSTALL_DIR}/tools/msobjdump`, where `${INSTALL_DIR}` should be replaced with the file storage path after the CANN software installation. Taking the root user installation as an example, the default file storage path after installation is /usr/local/Ascend/cann.

2.  Set the environment variables.
    -   When the Ascend-cann-toolkit package is installed by the root user

        ```
        source /usr/local/Ascend/cann/set_env.sh
        ```

    -   When the Ascend-cann-toolkit package is installed by a non-root user

        ```
        source ${HOME}/Ascend/cann/set_env.sh
        ```

3.  Check whether the tool is installed successfully.

    Run the following command. If the --help or -h information is displayed normally, the tool environment is normal and the functions can be used properly.

    ```
    msobjdump -h
    ```

## Command Format<a name="section101202511916"></a>

-   **Command for parsing an ELF file**

    ```
    msobjdump --dump-elf <elf_file> [--verbose]
    ```

    **Table 1**  Parameter description<a name="table167911947163519"></a>

    | Parameter (Case-Sensitive) | Optional/Required | Description |
    | ---- | ---- | ---- |
    | `--dump-elf <elf_file>`, `-d` | Required | Parses the device information contained in the ELF file, such as the file name, file type, file length, and symbol table, and displays it on the terminal screen.<br>`<elf_file>` indicates the path of the ELF file to be parsed, for example, `/home/op_api/lib_api.so`. Two print modes are supported:<br>Simple print: By default, only part of the device information is printed.<br>Full print: Used together with `--verbose` to enable full device information display on the screen.<br>For the print fields of the kernel function direct call project and the custom operator project, see <a href="#table94384560259">Table 4</a> and <a href="#table-aclnn-meta-fields">Table 5</a>, respectively. |
    | `--verbose`, `-V` | Optional | Must be used together with `--dump-elf` to enable full device information printing in the ELF file. |

-   **Command for extracting an ELF file**

    ```
    msobjdump --extract-elf <elf_file> [--out-dir <out_path>]
    ```

    **Table 2**  Parameter description<a name="table131531242133819"></a>

    | Parameter (Case-Sensitive) | Optional/Required | Description |
    | ---- | ---- | ---- |
    | `--extract-elf <elf_file>`,`-e` | Required | Extracts the device information contained in the ELF file and saves the parsed results to the output path.<br>`<elf_file>` indicates the path of the ELF file to be extracted, for example, `/home/op_api/lib_api.so`.<br>Default path: The extracted result files are saved to the current execution path by default.<br>Custom path: Can be used together with `--out-dir` to set the save path. |
    | `--out-dir <out_path>`,`-o` | Optional | Must be used together with `--extract-elf` to set the save path of the extracted files.<br>`<out_path>` is the directory for the saved files, for example, `/home/extract/`.<br>**Note**: `msobjdump` supports concurrent call by multiple users, but different `--out-dir` values must be specified; otherwise, the saved content may be overwritten. |

-   **Command for obtaining the ELF file list**

    ```
    msobjdump --list-elf <elf_file>
    ```

    **Table 3** Parameters

    <a name="table121952819427"></a>

    | Parameter (Case-Sensitive) | Optional/Required | Description |
    | ---- | ---- | ---- |
    | `--list-elf <elf_file>`,`-l` | Required | Obtains the list of device information files contained in the ELF file and prints them.<br>`<elf_file>` indicates the path of the ELF file to be printed, for example, `/home/op_api/lib_api.so`. |

## Usage Example (Kernel Function Direct Call Project)<a name="section_fusion_compile_msobjdump"></a>

Take the executable file generated by a kernel function direct call project as an example. Assume that `${build_dir}` is the project build directory and the generated executable file is named `demo`. For such artifacts, the tool parses them based on the device-related information in the executable file. Among them, `--dump-elf` is used to display binary meta and function meta information, `--list-elf` is used to view the extractable device file names, and `--extract-elf` is used to write the parsed device files to disk. For call examples, see [msobjdump example](https://gitcode.com/cann/asc-tools/tree/9.2.0/examples/04_msobjdump).

-   **Parse the artifact of a kernel function direct call project**

    Two print methods are supported. Select one as needed. For the meaning of parsing fields, see [Table 4](#table94384560259).

    -   Simple print

        ```
        msobjdump --dump-elf ${build_dir}/demo
        ```

        Run the above command. The terminal prints the basic device information. The following is an example:

        ```
        .ascend.meta META INFO
        RUNTIME_IMPLICIT_INFO: L2Cache Hint Flag
        RUNTIME_IMPLICIT_INFO: Hardware Sync Flag
        VERSION: 1
        RUNTIME_IMPLICIT_INFO: SIMD Printf Flag
        .ascend.meta. [0]: _Z23matmul_leakyrelu_customPhS_S_S_S_N7AscendC6tiling11TCubeTilingE_mix_aic
        KERNEL_TYPE: MIX_AIC_MAIN
        CROSS_CORE_SYNC: USE_SYNC
        MIX_TASK_RATION: [1:2]
        .ascend.meta. [1]: _Z23matmul_leakyrelu_customPhS_S_S_S_N7AscendC6tiling11TCubeTilingE_mix_aiv
        KERNEL_TYPE: MIX_AIC_MAIN
        CROSS_CORE_SYNC: USE_SYNC
        MIX_TASK_RATION: [1:2]
        ```

    -   Full print

        ```
        msobjdump --dump-elf ${build_dir}/demo --verbose
        ```

-   **Obtain the device file list in the artifact of a kernel function direct call project**

    ```
    msobjdump --list-elf ${build_dir}/demo
    ```

    Run the above command. The terminal prints the names of extractable device files. The screen display information is as follows:

    ```
    ELF file    0: demo.aicore.o
    ```

-   **Extract the device files in the artifact of a kernel function direct call project and write them to disk**

    ```
    msobjdump --extract-elf ${build_dir}/demo
    ```

    After the preceding command is executed, the `demo.aicore.o` file is saved to the current execution path by default. To specify an output path, use it together with `--out-dir`.

## Example (Custom Operator Project)<a name="section12835815105114"></a>

Take the AddCustom operator in the [custom operator project example](../../../../../examples/01_simd_cpp_api/02_features/99_acl_based/00_acl_compilation/custom_op/README.md) as an example. If the sample root directory is `${sample_dir}`, run the following command:

```bash
cd ${sample_dir}
mkdir -p build && cd build
cmake .. && make -j binary package
```

After compilation, the Device-side ELF file of the AddCustom operator is located in the `build/op_kernel/ascendc_kernels/binary/${soc_version}/add_custom/` directory. The hash value in the file name is generated from the compilation input and is subject to the actual artifact. For the meaning of the parsed fields, see [Table 5](#table-aclnn-meta-fields).

```bash
msobjdump --dump-elf ${sample_dir}/build/op_kernel/ascendc_kernels/binary/ascend950/add_custom/AddCustom_*.o
```

Run the above command. The terminal prints the basic device information. The following is an example:

```text
.ascend.meta META INFO
VERSION: 1
DEBUG: debugBufSize=0, debugOptions=0
DYNAMIC_PARAM: dynamicParamMode=0
OPTIONAL_PARAM: optionalInputMode=1, optionalOutputMode=1
.ascend.meta. [0]: AddCustom_ab1b6750d7f510985325b603cb06dc8b_0
KERNEL_TYPE: AIV
DETERMINISTIC_INFO: 1
BLOCK_NUM: 0xFFFFFFFF
FUNCTION_ENTRY: 0
```

To view detailed information such as the ELF header, sections, and symbols, add the `--verbose` parameter to the preceding command.
