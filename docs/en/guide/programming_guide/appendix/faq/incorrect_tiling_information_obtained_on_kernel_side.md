# Incorrect Tiling Information Is Obtained on the Kernel Side<a name="ZH-CN_TOPIC_0000001750140252"></a>

<!-- md-trans-meta sourceCommit=703a1278c565e078962927f6894d30d5e9a7c1ec translatedAt=2026-08-26T11:25:21.920Z pushedAt=2026-08-31T10:57:49.793Z -->

## Symptoms<a name="section151611254194612"></a>

When PRINTF is added to the operator implementation code on the kernel side, the printed output shows that the kernel side obtains incorrect tiling information.

For example, in the following sample, the added print code is as follows:

```
PRINTF("tiling_data.totalLength: %d tiling_data.tileNum: %d.\n", tiling_data.totalLength, tiling_data.tileNum);
```

The printed tiling data is as follows, all zeros:

```
tiling_data.totalLength: 0 tiling_data.tileNum: 0.
```

## Root Cause<a name="section417961104715"></a>

The incorrect tiling information obtained on the kernel side is generally caused by either of the following:

-   The tiling calculation logic on the host side is incorrect.
-   The parameters of the kernel-side function are not filled in the correct order.

## Procedure<a name="section166318242419"></a>

1.  Refer to the following example to print the TilingData and check whether the TilingData serialized and saved on the host side is correct. If the printed value is incorrect, the tiling calculation logic may be incorrect. In this case, further check the tiling implementation code on the host side to locate the error in the calculation logic.

    ```
    std::cout<<*reinterpret_cast<uint32_t *>(context->GetRawTilingData()->GetData())<<std::endl; // Print the value of the first TilingData parameter based on the actual data type. To check other values, offset the value pointer forward.
    ```

2.  If the TilingData printed in the previous step is correct, check whether the parameters of the kernel function on the kernel side are filled in the correct order.

    When you use the msOpGen tool to create an operator project and develop the kernel-side operator based on the project, the kernel function definition template is automatically generated by the msOpGen tool, as shown in the following example. The parameters are arranged in the order of "input, output, workspace, tiling". Check whether the parameter order has been adjusted and is inconsistent with the correct order.

    ```
    #include "kernel_operator.h"
    extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR workspace, GM_ADDR tiling) {
        GET_TILING_DATA(tiling_data, tiling);// Obtain the tiling parameters.
        // TODO: user kernel impl
    }
    ```
