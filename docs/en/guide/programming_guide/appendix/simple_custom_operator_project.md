# Simple Custom Operator Project<a name="ZH-CN_TOPIC_0000001938509805"></a>

The simple custom operator project described in this section is a simplified version of the custom operator project described above. It simplifies the compilation, packaging, and deployment of operators, making it easier for developers to integrate this project into their own operator projects.

> [!NOTE] Note
> - This project supports custom operator development on the following platforms:
>     - Atlas A2 training products
>     - Atlas inference products
> - Operators developed with this project can be called only through the single-operator API (aclnn).
> - This project does not support cross-compilation of operators.

## Creating an Operator Project<a name="section916885273914"></a>

Similar to [Creating an Operator Project](../advanced_programming/aclnn_operator_development/operator_project_creation.md), a simple custom operator project is generated by msOpGen. Based on the operator prototype definition, it outputs an operator project, including the **operator host-side code implementation file**, the **operator kernel-side implementation file**, and the **project compilation configuration file**. The main difference is that creating a simple operator project requires configuring the framework as aclnn through the **-f** parameter.

The procedure for creating a simple operator development project using the msOpGen tool is as follows:

1.  Write the operator prototype definition JSON file, which is used to generate the operator development project.

    For example, the JSON file of the AddCustom operator is named add\_custom.json, and its content is as follows:

    ```
    [
        {
            "op": "AddCustom",
            "input_desc": [
                {
                    "name": "x",
                    "param_type": "required",
                    "format": [
                        "ND",
                        "ND",
                        "ND"
                    ],
                    "type": [
                        "fp16",
                        "float",
                        "int32"
                    ]
                },
                {
                    "name": "y",
                    "param_type": "required",
                    "format": [
                        "ND",
                        "ND",
                        "ND"
                    ],
                    "type": [
                        "fp16",
                        "float",
                        "int32"
                    ]
                }
            ],
            "output_desc": [
                {
                    "name": "z",
                    "param_type": "required",
                    "format": [
                        "ND",
                        "ND",
                        "ND"
                    ],
                    "type": [
                        "fp16",
                        "float",
                        "int32"
                    ]
                }
            ]
        }
    ]
    ```

2.  Use the msOpGen tool to generate the operator development project. Taking the generation of the AddCustom operator project as an example, only the key parameters are explained below. For details about the parameters, see [*msOpGen User Guide*](https://gitcode.com/Ascend/msopgen/blob/26.1.0/docs/en/user_guide/msopgen_user_guide.md).

    ```
    ${INSTALL_DIR}/python/site-packages/bin/msopgen gen -i $HOME/sample/add_custom.json -c ai_core-<soc_version> -lan cpp -out $HOME/sample/AddCustom -f aclnn
    ```

    -   $\{INSTALL\_DIR\} is the path where the CANN software is stored after installation. Replace it based on the actual environment.
    -   -i: specifies the path of the operator prototype definition file _add\_custom_.json. Modify it based on the actual situation.
    -   -c: `ai_core-_<soc_version>` indicates that the operator runs on the AI Core, where _<soc\_version\>_ is the model of the Ascend AI processor.


    -   -lan: the parameter cpp indicates that the operator is developed using the C/C++ programming language based on the Ascend C programming framework.
    -   -out: path for storing the generated files. It can be configured as an absolute path or a relative path, and the user executing the tool must have read and write permissions on the path. If it is not configured, the files are generated in the current directory where the command is executed by default.
    -   -f: framework type. aclnn indicates that a simple project is generated.

3.  After the command is executed, an operator project directory is generated in the directory specified by -out or in the default path. The project contains template files for operator implementation, compilation scripts, and so on. Taking the AddCustom operator as an example, the directory structure is as follows:

    ```
    AddCustom
    ├── build.sh                        // Compilation entry script
    ├── cmake 
    │   ├── config.cmake              // Compilation configuration items
    │   ├── func.cmake
    │   ├── intf.cmake
    │   └── util                       // Directory for storing scripts and common compilation files required for compiling the operator project
    ├── CMakeLists.txt                  // CMakeLists.txt of the operator project
    ├── op_host                         // Host-side implementation file
    │   ├── add_custom_tiling.h     // Operator tiling definition file
    │   ├── add_custom.cpp          // File containing operator prototype registration, tiling implementation, and other content
    │   ├── CMakeLists.txt
    ├── op_kernel                       // kernel-side implementation files
    │   ├── CMakeLists.txt   
    │   ├── add_custom.cpp          // operator code implementation file
    ```

    >[!NOTE] Note
    >The bold files in the directory structure above are the files that need to be modified during subsequent operator development. Other files do not need to be modified.

## Operator Compilation<a name="section1826554118418"></a>

After the kernel-side and host-side operator implementations are developed, the operator must be compiled to generate the operator static library. The aclnn call implementation code and header files are automatically generated, and the operator static library is linked to generate the aclnn dynamic library, so as to support subsequent operator call through the single operator API (aclnn). The compilation process is as follows:

-   Automatically generate the aclnn API file **aclnn\_\*.h** and the aclnn implementation file **aclnn\_.cpp** based on the host-side operator implementation file.
-   Compile the tiling implementation and the operator prototype definition to generate the tiling dynamic library **liboptiling.so** (**libcust\_opmaster\_rt2.0**).
-   Compile the kernel-side operator implementation file and load the tiling dynamic library to generate the kernel static library **libkernels.a**.
-   Compile the aclnn implementation file and link the kernel static library **libkernels.a** to generate the dynamic library **libcust\_opapi.so** for single-operator API call.

The process described above is encapsulated in the compilation script. Developers can perform compilation by following the steps below:

1.  Complete the project compilation-related configuration.
    -   Modify the configuration items in **config.cmake** under the **cmake** directory. The content of the **config.cmake** file is as follows:

        ```
        set(CMAKE_CXX_FLAGS_DEBUG "")
        set(CMAKE_CXX_FLAGS_RELEASE "")
        
        if (NOT DEFINED CMAKE_BUILD_TYPE)
            set(CMAKE_BUILD_TYPE Release CACHE STRING "")
        endif()
        if (CMAKE_INSTALL_PREFIX_INITIALIZED_TO_DEFAULT) 
            set(CMAKE_INSTALL_PREFIX "${CMAKE_SOURCE_DIR}/build_out" CACHE PATH "" FORCE)
        endif()
        if (NOT DEFINED ASCEND_CANN_PACKAGE_PATH)
            set(ASCEND_CANN_PACKAGE_PATH /usr/local/Ascend/cann CACHE PATH "") // Replace it with the actual path where the CANN package is installed.
        endif()
        if (NOT DEFINED ASCEND_PYTHON_EXECUTABLE)
            set(ASCEND_PYTHON_EXECUTABLE python3 CACHE STRING "")
        endif()
        if (NOT DEFINED ASCEND_COMPUTE_UNIT)
            set(ASCEND_COMPUTE_UNIT ascendxxx CACHE STRING "")
        endif()
        if (NOT DEFINED ENABLE_TEST)
            set(ENABLE_TEST FALSE CACHE BOOL "")
        endif()
        if (NOT DEFINED ENABLE_CROSS_COMPILE)
            set(ENABLE_CROSS_COMPILE  FALSE CACHE BOOL "")
        endif()
        if (NOT DEFINED CMAKE_CROSS_PLATFORM_COMPILER)
            set(CMAKE_CROSS_PLATFORM_COMPILER "/your/cross/compiler/path" CACHE PATH "")
        endif()
        set(ASCEND_TENSOR_COMPILER_PATH ${ASCEND_CANN_PACKAGE_PATH}/compiler)
        set(ASCEND_CCEC_COMPILER_PATH ${ASCEND_TENSOR_COMPILER_PATH}/ccec_compiler/bin)
        set(ASCEND_AUTOGEN_PATH ${CMAKE_BINARY_DIR}/autogen)
        file(MAKE_DIRECTORY ${ASCEND_AUTOGEN_PATH})
        set(CUSTOM_COMPILE_OPTIONS "custom_compile_options.ini")
        execute_process(COMMAND rm -rf ${ASCEND_AUTOGEN_PATH}/${CUSTOM_COMPILE_OPTIONS}
                        COMMAND touch ${ASCEND_AUTOGEN_PATH}/${CUSTOM_COMPILE_OPTIONS})
        ```

2.  (Optional) If multiple operators need to be compiled, add the operators to be compiled in the **CMakeLists.txt** under the **op\_kernel** directory.

    ```
     
    # set custom compile options
    if ("${CMAKE_BUILD_TYPE}x" STREQUAL "Debugx")
        add_ops_compile_options(ALL OPTIONS -g -O0)
    endif()
    # For multi-operator compilation, add the operator source files through the add_kernel_compile command.
    add_kernel_compile(AddCustom ${CMAKE_CURRENT_SOURCE_DIR}/add_custom.cpp)
    add_kernel_compile(SubCustom ${CMAKE_CURRENT_SOURCE_DIR}/sub_custom.cpp)
    if(ENABLE_TEST AND EXISTS ${CMAKE_CURRENT_SOURCE_DIR}/testcases)
        add_subdirectory(testcases)
    endif()
    ```

3.  (Optional) In the operator project, if developers want to add custom compilation options to the kernel-side code of the operator, refer to [Custom Compilation Options](../advanced_programming/aclnn_operator_development/operator_package_compilation/operator_project_compilation.md#section7321165972311) to customize the compilation options.
4.  Run the following command in the operator project directory to compile the operator project.

    ```
    ./build.sh
    ```

    After successful compilation, the generated aclnn header files and lib libraries are stored in the **CMAKE\_INSTALL\_PREFIX/op\_api** directory. Each operator corresponds to a separate header file. The specific directory structure is as follows:

    ```
    ├── op_api
    │   ├── include
    │       ├── aclnn_optype1.h
    │       └── aclnn_optype2.h
    │       └── aclnn_optypexxx.h
    │   ├── lib
    │       ├── libcust_opapi.so
    ```

    The library files generated in the lib directory can be further parsed using the msobjdump tool to obtain kernel information. For details, see the [msobjdump tool](msobjdump_tool.md).
