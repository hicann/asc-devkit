# 舍入模式与饱和模式

## 概述

Tensor API通过`cast`接口完成寄存器数据类型转换。对于可能发生精度损失或数值溢出的转换，可以通过编译期`cast_options`指定舍入模式和饱和模式：

- **舍入模式**：指定精度损失时的舍入方向或规则。
- **饱和模式**：指定转换结果超出目的类型表示范围时的处理方式。

相关接口声明位于`tensor_api/experimental/arch/vector/type_conversion.h`，相关枚举定义位于`tensor_api/experimental/utils/reg_enum.h`。

## 舍入模式

`cast_round_mode`用于指定`cast`的舍入方式。Tensor API使用枚举值配置模式。

| 枚举值 | 说明 | 示例 |
| --- | --- | --- |
| rint | 舍入到最近值；正好位于中间值时舍入到偶数。 | 1.5 → 2，2.5 → 2 |
| round | 舍入到最近值；正好位于中间值时远离0。 | 1.5 → 2，-1.5 → -2 |
| floor | 向负无穷方向舍入。 | 1.7 → 1，-1.3 → -2 |
| ceil | 向正无穷方向舍入。 | 1.3 → 2，-1.7 → -1 |
| trunc | 向0方向舍入，直接截断小数部分。 | 1.7 → 1，-1.7 → -1 |
| odd | 最近邻奇数舍入，按照目的浮点格式的奇数舍入规则处理。当前仅`float → half`支持该模式。 | - |
| hybrid | 混合舍入模式，当前用于`float`或`half`转换为`hifloat8_t`。 | - |
| unknown | 未指定舍入方式的预留值。仅在对应类型转换支持该配置时使用。 | - |

### 配置规则

- 表中`rint`、`round`、`floor`、`ceil`和`trunc`的示例以浮点转整数为例。浮点转浮点时，舍入目标是目的格式能够表示的数，而不是整数。
- 舍入模式是`cast`模板参数`opt`的一部分，在编译期确定。
- 不同源类型和目的类型支持的舍入模式不同，必须按照[cast的数据类型](cast.md#数据类型)表配置。
- 不支持的类型、布局、舍入和饱和配置组合会触发编译期错误。
- 对不需要选择舍入方式的精确转换，必须使用`unknown`；具体取值以[cast的数据类型](cast.md#数据类型)表为准。

### 舍入过程举例

以下以范围内的`float → int16_t`转换为例，说明常用舍入模式对正数、负数和中间值的处理：

| 输入 | `rint` | `round` | `floor` | `ceil` | `trunc` |
| --- | --- | --- | --- | --- | --- |
| 1.4 | 1 | 1 | 1 | 2 | 1 |
| 1.5 | 2 | 2 | 1 | 2 | 1 |
| 2.5 | 2 | 3 | 2 | 3 | 2 |
| -1.4 | -1 | -1 | -2 | -1 | -1 |
| -1.5 | -2 | -2 | -2 | -1 | -1 |
| -2.5 | -2 | -3 | -3 | -2 | -2 |

其中，`rint`与`round`都选择最近值，但中间值的处理不同：`2.5`在`rint`模式下得到偶数`2`，在`round`模式下得到远离0的`3`。`floor`和`trunc`对负数的处理也不同：`-1.4`分别得到`-2`和`-1`。

`odd`用于目的浮点格式的奇数舍入，不能套用上述整数取整表。例如，`1.5`能够由`half`精确表示，转换为`half`时不能将其解释为整数`1`或`3`。`hybrid`用于`hifloat8_t`相关转换的混合舍入，不应按固定的向上、向下或向0取整规则理解。

## 饱和模式与非饱和模式

`cast_sat_mode`用于指定转换结果超出目的类型表示范围时的处理方式。

| 枚举值 | 说明 |
| --- | --- |
| not_sat | 非饱和模式。整数窄化转换超出范围时按目的格式截断；浮点转换保留目的浮点格式支持的特殊值。 |
| sat | 饱和模式。转换结果超出目的类型范围时钳位到目的类型边界。 |
| unknown | 不配置饱和模式的预留值，仅用于对应类型转换支持该配置的场景。 |

### 配置方法

开启饱和模式和非饱和模式时，需配置CTRL寄存器。通过[asc_get_ctrl接口](../../../c_api/spr/asc_get_ctrl.md)保存当前值，仅修改所需比特位，并在相关计算结束后恢复原值。

| CTRL比特位 | 作用 | 配置值 |
| --- | --- | --- |
| CTRL[60] | 选择单指令/API配置或全局饱和配置。 | 0：使用单指令/API配置；1：使用全局配置。 |
| CTRL[59] | 控制浮点转整数、整数转整数的全局转换饱和模式，仅在`CTRL[60] = 1`时生效。 | 0：饱和；1：截断。 |
| CTRL[48] | 控制浮点计算及部分浮点精度转换的全局饱和行为。 | 0：饱和，INF钳位到对应有限边界、NaN转换为0；1：非饱和，保留INF和NaN。 |
| CTRL[50] | 控制`fp8_e8m0_t`、`fp8_e5m2_t`、`fp8_e4m3fn_t`相关场景的全局饱和模式。 | 0：饱和；1：非饱和。 |

#### 按cast_options配置

希望通过`cast_options::sat`分别选择每条转换的饱和行为时，将`CTRL[60]`设置为`0`，再使用`cast_sat_mode::sat`或`cast_sat_mode::not_sat`调用`cast`。CTRL配置在SIMD VF外、执行相关转换之前完成；相关计算结束后恢复：

```cpp
#include "c_api/spr/spr.h"

const uint64_t saved_ctrl = static_cast<uint64_t>(asc_get_ctrl());
const uint64_t api_ctrl = saved_ctrl & ~(uint64_t{1} << 60);
asc_set_ctrl(api_ctrl);
```

执行本页[配置示例](#配置示例)所示的寄存器转换后，在SIMD VF外恢复：

```cpp
asc_set_ctrl(saved_ctrl);
```

#### 按全局CTRL配置

对于浮点转整数或整数转整数，若使用全局模式，将`CTRL[60]`设置为`1`，并通过`CTRL[59]`指定饱和或截断。以下为全局饱和模式的配置片段：

```cpp
const uint64_t saved_ctrl = static_cast<uint64_t>(asc_get_ctrl());
const uint64_t global_sat_ctrl = (saved_ctrl | (uint64_t{1} << 60)) & ~(uint64_t{1} << 59);
asc_set_ctrl(global_sat_ctrl);
```

若改为全局截断模式，则使用`asc_set_ctrl(global_sat_ctrl | (uint64_t{1} << 59))`。全局模式下不能仅根据`cast_options::sat`判断最终饱和行为，且仍须传入该类型组合支持的`cast_options`。转换结束后同样使用`asc_set_ctrl(saved_ctrl)`恢复。

浮点转浮点场景应根据目的类型配置`CTRL[48]`及适用的`CTRL[50]`，不能用`CTRL[59]`代替。`FLOAT`全局饱和需要先启用全局策略；`FLOAT8`饱和还需要先启用`FLOAT`饱和。各模式的适用范围和配置约束请参考[asc_set_ctrl](../../../c_api/spr/asc_set_ctrl.md)和[asc_set_saturation_flag](../../../c_api/spr/asc_set_saturation_flag.md)。修改CTRL会影响当前核上其他受这些比特位控制的计算，不能直接写入一个固定值而覆盖无关配置。

### 模式对比

不同转换场景下的行为如下；具体类型转换是否支持`not_sat`或`sat`，以[cast的数据类型](cast.md#数据类型)表为准。

| 转换场景 | `not_sat` | `sat` |
| --- | --- | --- |
| 浮点转整数 | 超出范围时按目的格式截断；正负无穷返回目的类型对应边界值；NaN返回0。 | 超出范围时返回目的类型边界值；正负无穷分别钳位到对应边界；NaN返回0。 |
| 浮点转浮点 | 目的类型支持时保留NaN和正负无穷；有限值超出范围时按目的浮点格式转换。 | 超出范围时钳位到目的浮点类型边界；NaN转换为0。 |
| 整数转浮点 | 该场景不提供饱和模式，使用舍入模式控制可能的精度损失。 | 不支持。 |
| 整数转整数 | 窄化转换超出范围时截断为目的格式的数据宽度；扩宽转换通常保持数值。 | 超出范围时钳位到目的类型边界。 |

例如，`int32_t`转换为`uint8_t`时，输入`256`在`not_sat`模式下结果为`0`，在`sat`模式下结果为`255`；输入`-1`在`sat`模式下结果为`0`。

### 整数转整数示例

以`int32_t → uint8_t`为例，非饱和模式保留低8 bit，而不是将数值钳位到范围内：

| 输入 | 非饱和结果 | 饱和结果 |
| --- | --- | --- |
| 100 | 100 | 100 |
| 256（0x00000100） | 0（0x00） | 255 |
| 511（0x000001FF） | 255（0xFF） | 255 |
| -1（0xFFFFFFFF） | 255（0xFF） | 0 |

扩宽转换通常保持数值，但不能据此推断任意有符号到无符号转换。例如，`int16_t → uint32_t`要求`opt.sat`为`unknown`，负数转换为`0`。请以[cast的数据类型说明](cast.md#数据类型)和对应转换约束为准。

### 浮点转整数示例

以`float → int16_t`为例，先按所选舍入模式处理小数部分，再按有效的饱和配置处理超出目的类型范围的结果。下表使用`rint`：

| 输入 | 非饱和结果 | 饱和结果 |
| --- | --- | --- |
| 2.5 | 2 | 2 |
| 40000.0 | -25536，保留低16 bit | 32767 |
| -40000.0 | 25536，保留低16 bit | -32768 |
| 正无穷 | 32767 | 32767 |
| 负无穷 | -32768 | -32768 |
| NaN | 0 | 0 |

### 浮点转浮点示例

以`float → half`为例，目的类型最大有限正数为`65504.0`。下表使用`rint`，并假设CTRL已按对应模式配置：

| 输入 | 非饱和结果 | 饱和结果 |
| --- | --- | --- |
| 1.5 | 1.5 | 1.5 |
| 70000.0 | 正无穷 | 65504.0 |
| -70000.0 | 负无穷 | -65504.0 |
| 正无穷 | 正无穷 | 65504.0 |
| 负无穷 | 负无穷 | -65504.0 |
| NaN | NaN | 0 |

上述结果不能推广到所有低精度浮点格式或所有舍入模式。其他目的格式对NaN、无穷和有限溢出值的处理，以对应类型转换的约束为准。

## 配置示例

以下片段在SIMD VF或SIMD被调函数内将`float`转换为`half`，使用向最近偶数舍入和饱和模式。`src`为已完成数据和mask初始化的`reg_tensor<float>`，调用前须按[配置方法](#配置方法)设置CTRL饱和策略：

```cpp
static constexpr asc::te::experimental::cast_options options = {
    asc::te::experimental::cast_layout::zero,
    asc::te::experimental::cast_round_mode::rint,
    asc::te::experimental::cast_sat_mode::sat,
};

auto dst = asc::te::experimental::cast<half, options>(src);
```

`cast_layout`用于描述源、目的类型位宽不同时较小元素在寄存器中的位置，不属于舍入或饱和模式。具体布局要求请参考[cast_layout](../aux_data_types/cast_layout.md)。
