# NPU架构版本3510

本节介绍硬件约束以及解决方案建议。对应的产品型号为：

<!-- npu="950" id1 -->
-   Ascend 950PR&950DT系列产品
<!-- end id1 -->

**表1**  硬件约束以及解决方案建议

| 分类 | 硬件约束描述 | 解决方案建议 |
| --- | --- | --- |
| 内存访问对齐约束 | 各存储单元的最小访问粒度/地址对齐要求：<br> Unified Buffer：32Byte对齐。<br> L1 Buffer：32Byte对齐。<br> L0A Buffer/L0B Buffer：512Byte对齐。<br> L0C Buffer：64/1024Byte对齐。<br> BiasTable Buffer：64Byte对齐。<br> Fixpipe Buffer：64/128Byte对齐。 | 进行数据搬运时，需要感知对齐约束。<br> 针对UB，对于非对齐场景，可使用非对齐搬入LoadUnAlign和非对齐搬出StoreUnAlign指令进行处理，可支持1Byte对齐访问。其中首地址非对齐连续访问时性能与对齐场景基本一致，首地址非对齐非连续访问时，计算bound场景下不受影响，UB访存bound会受影响。<br> 针对L0C Buffer，Mmad计算时以1024B对齐，矩阵计算搬出时以64B对齐。<br> 针对Fixpipe Buffer，relu场景下以64B对齐，quant场景以128B对齐。 |
| API通用约束 | 使用Ascend C基础API时，源操作数和目的操作数的地址重叠通用约束。 | 使用基础API的Tensor高维切分计算接口时，为了节省地址空间，开发者可以定义一个Tensor，供源操作数与目的操作数同时使用（即地址重叠）。使用时需要注意以下约束：<br> - 单次迭代内：源操作数与目的操作数必须100%完全重叠，不支持部分重叠。<br>- 多次迭代间：不支持前序迭代的目的操作数与后序迭代的源操作数重叠。例如，第N次迭代的目的操作数是第N+1次的源操作数。在这种情况下，第N次迭代可能会改写覆盖源操作数的数值，导致无法得到预期结果。特别地，对于部分双目计算类的API（Add、Sub、Mul、Max、Min、AddRelu、SubRelu），当数据类型为half、int32_t、float时，支持前序迭代的目的操作数与后序迭代的源操作数重叠：仅针对目的操作数和第二个源操作数重叠的情况，且src1RepStride或者dstRepStride必须为0。 |
| 内存访问（GM） | 单次搬运数据长度16KB以上时，可发挥带宽的最佳性能。 | 根据实测经验，单次搬运数据长度16KB以上时，通常能较好地发挥出带宽的最佳性能。因此对于单次搬运，应考虑尽可能的搬运较大的数据块（不同芯片不一样）。<br> 具体解决方案可参考[尽量一次搬运较大的数据块](../../../../operator_practice/simd_operator_optimization/memory_access/transfer_larger_data_blocks.md)章节。 |
| 内存访问（GM） | 数据搬运会被拆成128B/256B/512B不同长度进行搬运，非对齐会向上取整。 | Tiling尽量让搬运的内轴128B、256B、512B对齐。<br> 具体解决方案可参考[GM地址尽量512B对齐](../../../../operator_practice/simd_operator_optimization/memory_access/gm_address_512b_alignment.md)章节。 |
| 内存访问（UB） | UB bank访问冲突（Vector计算访问/搬运访问）。 | UB需要按照芯片要求，在软件实现时错开处理的地址，从而解决bank冲突。具体解决方案可参考[避免bank冲突（NPU架构版本3510）](../../../../operator_practice/simd_operator_optimization/memory_access/avoid_ub_bank_conflict/avoid_bank_conflict_npu_arch_3510.md)章节。 |
| Vector计算 | Ln、Exp、Sqrt、Rsqrt、Reciprocal、Div等接口不支持Subnormal计算。 | Ln、Exp、Sqrt、Rsqrt、Reciprocal、Div接口在3510上若需要支持Subnormal计算，需要配置对应的FTZ_FALSE算法，参考[兼容性迁移指南-删除Subnormal硬件计算功能](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#subnormal-migration)。 |
| Cube数据搬运 | 删除L1 Buffer到GM的数据通路。 | 兼容方案如下：<br> 1. 对于纯Cube侧算子，可以走L1 Buffer -> L0A Buffer/L0B Buffer -> L0C Buffer -> GM这一组数据通路；<br> 2. 对于Cube+Vector的融合算子，可走L1 Buffer -> UB -> GM。<br> 参考[兼容性迁移指南-删除支持L1 Buffer->GM硬件通路](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#data-copy-l1-to-gm-migration)。 |
| Cube数据搬运 | 删除GM到L0A Buffer的数据通路。 | 将原本GM->L0A Buffer的LoadData 2D数据搬运拆分为两部分：<br> 1. GM -> L1 Buffer（使用LoadData 2D矩阵搬运）；<br> 2. L1 Buffer -> L0A Buffer（使用LoadData 2D矩阵搬运）。<br> 参考[兼容性迁移指南-删除GM->L0A Buffer/L0B Buffer通路](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#gm-to-l0a-l0b-migration)。 |
| Cube数据搬运 | 删除GM到L0B Buffer的数据通路。 | 将原本GM->L0B Buffer的LoadData 2D数据搬运拆分为两部分：<br> 1. GM -> L1 Buffer（使用LoadData 2D矩阵搬运）；<br> 2. L1 Buffer -> L0B Buffer（使用LoadData 2D矩阵搬运）。<br> 参考[兼容性迁移指南-删除GM->L0A Buffer/L0B Buffer通路](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#gm-to-l0a-l0b-migration)。 |
| Cube数据搬运 | 在使用LoadData（卷积数据搬运）时，不再支持SetLoadDataBoundary接口。 | 兼容方案如下：<br> 1. 当2201版本上SetLoadDataBoundary的值为0时，在3510直接移除调用即可；<br> 2. 当2201版本上SetLoadDataBoundary的值为非0时，把一次搬运拆成多次LoadData，显式更新源/目的偏移实现绕回。<br> 详情参考[兼容性迁移指南-不支持设置L1 Buffer边界值](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#set-load-data-boundary-migration)。 |
| Cube数据搬运 | Fill接口不支持L0A/L0B的初始化。 | 兼容方案如下：<br> 1. 调用Fill接口，完成L1 Buffer上的初始化；<br> 2. 用LoadData 2D矩阵将数据搬运搬到L0A/L0B。<br> 参考[兼容性迁移指南-删除L0A Buffer/L0B Buffer初始化的相关硬件指令](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#fill-l0a-l0b-migration)。 |
| Cube数据搬运 | Cube数据搬入不支持int4b_t数据类型。 | 兼容方案如下：<br> 1. 可使用fp4x2_e2m1_t、fp4x2_e1m2_t进行搬运，具体可参考：[LoadData（2D矩阵搬运MX）](../../../../../api/SIMD-API/basic_api/cube_compute_ISASI/cube_compute_load/LoadData_2D_MX.md)；<br> 2. 在Vector上把int4b_t数据类型转化为int8_t数据类型；<br> 3. 利用UB->L1数据通路，将数据搬运到L1 Buffer。<br> 参考[兼容性迁移指南-Cube计算单元不再支持int4b_t数据类型](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#cube-int4-migration)。 |
| Cube数据搬运 | LoadDataWithTranspose接口不支持L1->L0A通路。 | 替换为其它搬运接口，如[LoadData（2D矩阵搬运V2）](../../../../../api/SIMD-API/basic_api/cube_compute_ISASI/cube_compute_load/LoadData_2D_V2.md)矩阵搬运。 |
| Cube数据搬运/Cube计算 | L0A矩阵分形从Zz变为Nz。 | 分形的转换涉及到以下两种典型场景的兼容性适配：<br> 1. L0A不复用。对一整块A矩阵进行一次mmad计算。<br> 2. L0A复用。切分M轴，A矩阵分为两块子矩阵，进行两次mmad计算。<br> 对于场景1，需要修改L1>L0A搬运过程的逻辑，由Nz->Zz分形转换变为Nz->Nz。具体可参考样例实现。<br> 对于场景2，在2201版本上，由于Zz分形本身在M轴上连续，所以L1->L0A搬运逻辑和场景1相同，而对于Ascend 950PR&950DT系列产品，切分M轴会导致矩阵不连续，需要拆分为两个Nz矩阵。具体可参考样例实现。<br> 详情可参考样例：[pattern_transformation](../../../../../../../examples/01_simd_cpp_api/06_compatibility_guide/pattern_transformation/README.md)。 |
| Cube数据搬运/Cube计算 | 不支持4:2结构化稀疏矩阵计算，以下指令不支持：LoadDataWithSparse、MmadWithSparse。 | 移除该加载路径，保留/恢复稠密B矩阵布局，可使用普通LoadData和Mmad。参考[兼容性迁移指南-删除4:2结构化稀疏功能](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#structured-sparsity-migration)。 |
| Cube计算 | Cube计算不支持int4b_t数据类型。 | 兼容方案如下：<br> 1. 在Vector上把int4b_t数据类型转化为int8_t数据类型；<br> 2. 利用UB->L1数据通路，将数据搬运到L1 Buffer。<br> 参考[兼容性迁移指南-Cube计算单元不再支持int4b_t数据类型](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#cube-int4-migration)。 |
| Cube计算 | Cube计算场景float算力为half算力的1/16。 | Cube计算场景float算力为half算力的1/16，建议使用[HF32](../../../../../api/SIMD-API/basic_api/cube_compute_ISASI/mmad_compute_key_features/HF32.md)特性，算力为half算力的1/2，更多理论算力规格可参考[Cube指令理论性能汇总](../../../../../api/appendix/cube_instruction_theoretical_perf_summary.md)章节。 |
| 指令队列深度 | Cube/Vector计算单元和搬运单元的指令队列存在深度规格，对应的指令队列达到最大深度时会阻塞该Cube/Vector核上其他全部指令下发，可能引起流水断流。 | 队列深度表示同一指令队列中可缓存的待执行指令数量。当其中任一待执行指令（Vector指令队列、Cube指令队列、MTE1/MTE2/MTE3指令队列等）数量达到队列深度时，对应的Scalar单元如果再次向该指令队列发射指令会被阻塞，导致Scalar单元无法继续顺序发射后续指令，可通过优化指令数量等方式进行性能优化，更多说明请参考[典型的指令流](../basic_architecture.md#典型的指令流)，具体的规格请参考[3510指令队列深度](../architecture_spec/npu_arch_3510.md#指令队列深度)。 |
| 流水同步（核内） | set/wait同步不匹配，状态会残留，影响后续算子。 | 通过孪生调试/mssanitizer工具，提前识别此类问题。 |
| 流水同步（核内） | 相同流水、相同eventID下，连续使用SetFlag会引发未定义行为，例如：<br> AscendC::SetFlag&lt;AscendC::HardEvent::M_MTE1&gt;(0);<br> AscendC::SetFlag&lt;AscendC::HardEvent::M_MTE1&gt;(0); | 通过孪生调试/mssanitizer工具，提前识别此类问题。 |
| 流水同步（核间） | 使用核间同步接口的核函数必须用[mix函数限定符](../../../language_extension/simd_builtin_keywords.md#函数执行空间限定符)。 | 通过孪生调试/mssanitizer工具，提前识别此类问题。 |
| 流水同步（核间） | [CrossCoreSetFlag](../../../../../api/SIMD-API/basic_api/sync_control/inter_core_sync/CrossCoreSetFlag_ISASI.md)和[CrossCoreWaitFlag](../../../../../api/SIMD-API/basic_api/sync_control/inter_core_sync/CrossCoreWaitFlag_ISASI.md)模式为0、1、2时，模板参数pipe不支持设置为PIPE_ALL，PIPE_S。模式4不支持PIPE_ALL。详情参考[新增核间同步控制模式4](../../../../cross_gen_migration_guide/instructions_for_new_features/3510_new_features.md#section_crosscore)。 | 通过孪生调试/mssanitizer工具，提前识别此类问题。 |
| 流水同步（核间） | CrossCoreSetFlag计数器存在限制，超出15次需要做一次反向同步，否则会出现卡死。 | 通过孪生调试/mssanitizer工具，超出场景提前报错。 |
| Scalar | 标量写GM时，数据会被缓存在DCache。硬件不保证DCache和GM一致性，需要用户保证。 | 可使用[DataCacheCleanAndInvalid](../../../../../api/SIMD-API/basic_api/cache_control/DataCacheCleanAndInvalid.md)来保证一致性，若预期不通过DCache读写数据，可通过[ReadGmBypassDCache](../../../../../api/SIMD-API/basic_api/scalar_compute/ReadGmBypassDCache_ISASI.md)/[WriteGmBypassDCache](../../../../../api/SIMD-API/basic_api/scalar_compute/WriteGmBypassDCache_ISASI.md)接口进行调用。详情参考[缓存一致性](../../memory_model/cache_coherence.md)。 |
| ICache | AIC ICache硬件规格限制32KB，AIV ICache硬件规格限制16KB。 | ICache位置在Scalar取指缓存，ICache大小在AIC和AIV侧存在差异，缓存一致性内容可参考[缓存一致性](../../memory_model/cache_coherence.md)章节。拆分Tiling_key或使用模板函数来减少代码段。详情见[多分支策略](../../../advanced_programming/aclnn_operator_development/design_and_implementation/multi_branch_strategy.md)。 |
| ICache | 不同核从同一个GM上访问指令数据并加载到ICache时，并行访问读取性能会下降。 | 小shape场景下可采取减少启动核数等优化手段，减少多核访问同一个GM上的数据。 |
| DCache | SIMD DCache硬件规格限制32KB，SIMT DCache硬件规格限制128KB。 | DCache位置在Scalar数据缓存，缓存一致性内容可参考[缓存一致性](../../memory_model/cache_coherence.md)章节。 |
| AIPP | 删除AIPP硬件指令并采用软仿，功能可迁移但性能可能下降。对应指令如下：SetAippFunctions、LoadImageToLocal。 | 对涉及AIPP硬件指令的算子重新进行性能评估。 |
| 调测 | 删除CheckLocalMemoryIA接口相关寄存器，不支持该调测API。 | 调测类接口，需要移除功能依赖。该接口为2201版本上的ISASI接口，950不保证兼容性。参考[兼容性迁移指南-不支持CheckLocalMemoryIA，硬件删除相关寄存器](../../../../cross_gen_migration_guide/3510_arch_migration/2201_to_3510_guide/basic_api_migration.md#check-local-memory-ia-migration)。 |
