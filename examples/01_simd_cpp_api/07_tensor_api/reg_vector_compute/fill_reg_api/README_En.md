# Fill Register API Sample

## Overview

This sample demonstrates scalar fill with the experimental Tensor API `asc::te::experimental::fill`. The kernel fills every element of the output tensor with the scalar value `1`.

## Supported Products and CANN Versions

| Product | CANN Version |
| --- | --- |
| Ascend 950PR/Ascend 950DT | CANN 9.1.0 or later |

## Sample Description

### Sample Function

The kernel fills every element of the output tensor with the scalar value `1`:

```text
y[i] = 1, 0 <= i < 256
```

### Sample Implementation

1. Create the output tensor in GM and UB by using `asc::te::make_tensor`, `asc::te::make_mem_ptr`, and `asc::te::make_frame_layout`.
2. Calculate the number of elements in a register operation as `asc_get_vf_len() / sizeof(T)` and determine the required number of iterations for all 256 elements.
3. Lock the Vector pipeline. During each iteration, call `asc::te::experimental::update_mask` to create the valid-element mask, then call `asc::te::experimental::fill(scalar, mask)` to fill a register tensor with scalar value `1`.
4. Store each register result to UB with `asc::te::experimental::store`, then unlock the Vector pipeline.
5. Lock the MTE3 pipeline and use Tensor API `copy` to move the output from UB to GM.
6. The host program launches the `fill` kernel with `<<<>>>`, writes the output to `output/output.bin`, and compares it with `output/golden.bin` generated by `scripts/gen_data.py`.

## Core Interface

### asc::te::experimental::fill

```cpp
template <size_t N = 1, typename T>
__simd_callee__ inline reg_tensor<T> fill(
    const T& value, const reg_tensor<bool>& mask = all_mask<T>());
```

This API fills the elements enabled by `mask` in a register tensor with `value` and returns the resulting register tensor. The current implementation supports `N == 1`.

## Build and Run

Run the following steps in the sample root directory.

### Configure Environment Variables

Configure the environment variables according to the CANN development toolkit installation path:

```bash
source ${install_path}/cann/set_env.sh
```

`${install_path}` is the CANN package installation directory. When no installation directory is specified, CANN is installed under `/usr/local/Ascend` by default.

### Run the Sample

```bash
mkdir -p build && cd build
cmake -DCMAKE_ASC_ARCHITECTURES=dav-3510 -DCANN_ASC_USE_EXPERIMENTAL=ON ..
make -j
python3 ../scripts/gen_data.py
./demo
```

To run the sample in NPU simulation mode, add `-DCMAKE_ASC_RUN_MODE=sim` to the CMake command:

```bash
cmake -DCMAKE_ASC_RUN_MODE=sim -DCMAKE_ASC_ARCHITECTURES=dav-3510 -DCANN_ASC_USE_EXPERIMENTAL=ON ..
make -j
```

When switching the run mode, clear the CMake cache in the `build` directory before reconfiguring the project.

### Build Options

| Option | Available Values | Description |
| --- | --- | --- |
| `CMAKE_ASC_RUN_MODE` | `npu` (default), `sim` | Operator execution mode: NPU execution or NPU simulation. |
| `CMAKE_ASC_ARCHITECTURES` | `dav-3510` | NPU architecture. `dav-3510` corresponds to Ascend 950PR/Ascend 950DT. |
| `CANN_ASC_USE_EXPERIMENTAL` | `ON` (required), `OFF` (default) | Enables experimental ASC APIs. |
